# 阅读站点设计说明（视觉模型）

本文件记录 `book/site/`（GitHub Pages 上的阅读站点）的**设计方案**：为什么这样分页、这样排、
这样切换语言。执行方案的是视觉模型：任务书 [`pipeline/prompts/design-reader-site.md`](../pipeline/prompts/design-reader-site.md)，
产出落在 [`pipeline/site/`](../pipeline/site/)（`index.html` / `toc.html` / `chapter.html` / `style.css` / `reader.js`），
组装脚本是 [`pipeline/build_site.py`](../pipeline/build_site.py)。

界面惯例的市场侧调研见 [research/reader-ui-patterns.md](research/reader-ui-patterns.md)；
本文只讲本项目的取舍。

## 1. 信息架构

| 页面 | 职责 |
| --- | --- |
| `index.html` | 作品与译本简介、开始/继续阅读、阅读体验说明、**GitHub 仓库与反馈渠道**、许可与免责 |
| `toc.html` | 32 章全展开目录（中文章名 + `Chapter N` + 地点日期 + 已读/当前标记），宽屏三列、窄屏单列 |
| `read/chapter-NN.html` | 正文。顶栏（主页/章名/目录/目录抽屉/语言/设置）、章标题区、双语正文、章末上一章·目录·下一章、底栏（翻屏 + 进度） |
| 目录抽屉 | 阅读页内快速跳章，不必回目录页 |
| 设置面板 | 字号 / 行距 / 中文段式 / 字体 / 主题 / 翻页 / 语言 / 同步滚动（默认开启） |

每章一个真实 URL（`read/chapter-NN.html`），带 `rel="prev"` / `rel="next"` / `rel="contents"`，
因此可以直接分享、加书签、被搜索引擎收录；站点是纯静态的，`file://` 打开也能完整阅读（不 fetch 任何数据）。

## 2. 阅读交互

- **两种翻页**：默认上下滚动（点击正文左右 1/3 翻一屏，步长 = 可见高 × 0.85）；可选左右翻页
  （CSS 多列 + 整列平移，`#page-indicator` 显示「第 x / y 页」）。到章末继续前进即进入下一章，
  到章首继续后退回到上一章，首末章回到目录。
- **底栏三段式**：左「上一章」/ 中「上一屏 · 进度 · 下一屏」/ 右「下一章」。中间的翻屏按钮文案随
  `data-page-mode` 在「屏/页」之间切换；两侧的章链接是真实 `<a>`，首章没有上一章、末章没有下一章
  （构建脚本加 `hidden`），窄屏下四个按钮收紧内边距、进度指示收窄字号，保证不横向溢出。
- **顶栏/底栏**：点击正文中部显隐；隐藏后只留 3px 进度线，正文不重排。
- **滚轮接管**（`main` 上的 `wheel` 监听）：指针在插图/终端面板这类**内部可滚动区块**上时先滚它自己，
  到顶或到底后再接续滚正文栏（面板不再带 `overscroll-behavior: contain`——那会让触摸拖拽整段失效，
  见 §5「移动端拖拽」；滚轮仍由脚本显式接管，行为不变）；中英分栏且整页还在顶部时，正文内向下滚
  **先把整页滚下去**，让上方的章标题区随滚动隐藏（否则两栏底部一段会被底栏挡住，只能靠在标题上滚动才露得出来）。
- **触摸**：手指拖拽一律交给浏览器原生滚动（终端面板只在横向有余量时横滚，纵向照常接续整页）；
  翻页模式补了横向滑动翻页（见 §5），纵向滑动与点击翻页区域的行为不变。
- **键盘**：`←/→` 翻页翻章、`↑/↓` 滚动、`Esc` 关面板或显隐菜单、`t` 循环主题、`d` 循环语言。
- **进度记忆**：章号、两种语言各自的滚动百分比/页码、字号、行距、字体、主题、语言、翻页模式、
  同步开关与中文段式都存 `localStorage["snowmoon.reader.v1"]`（只在本机，不上传，键名与结构是前端契约的一部分）。
  回到该章自动复位；主页据此显示「继续阅读」。
- **链接与控件不劫持点击**：点链接、按钮、输入框、选中文字、终端面板内部滚动区时不会误触发翻页。

## 3. 双语对照

三种语言模式：`中文`（默认）/ `English` / `对照`。

- 对照模式在**宽屏左右分栏**：英文在左、中文在右，两栏各自独立滚动，中缝一条分隔线，**默认按百分比同步滚动**。
- **窄屏分两个标签页**：中文 / English 切换，标签条固定在正文上方。
- 分栏还是标签页由可用空间**动态判定**，不是固定断点：记页面可用宽 `W`、可用高 `H`、字号 `F`，
  进入分栏要求 `W ≥ 60F + 64` 且 `W / H ≥ 1.15`；退出要求 `W < 60F + 32` 或 `W / H < 1.05`；
  两个条件之间保持现状（滞回，避免拖动窗口时闪烁）。`60F` 相当于「每栏至少 30 个汉字」，
  1366px 宽的常见桌面窗口即可分栏。
  这里量的是**页面可用空间**（视口宽 − 页边距、再夹到分栏容器 `min(76em + 32px)` 上限；高＝视口高 − 顶栏 − 底栏），
  不是 `#reader-main` 的实测尺寸——后者在标签页/单栏下被 `max-width: 38em` 限宽、高度又是整篇正文的自然高度，
  拿它判分会形成死锁：窗口一旦变窄掉进标签页，就再也量不到分栏所需的宽度（详见 §5）。
  判据重算同时挂在 `ResizeObserver`（正文容器）与 `window.resize`（视口）上，避免漏掉一次回调就停在窄屏样式。
- 不做逐段硬对齐：原文与译文段落一一对应，但句长差异大，强制对齐会造成错位；
  同步滚动按百分比即可。对照滚轮同步是**同步写入**另一栏（不再推迟到 `requestAnimationFrame`），
  避免无帧环境下对栏停在原位。
- 插图是**中文重绘版**，对照分栏时只在中文栏出现一次，避免同一张图左右各一份（见下文「集成修正」）。

## 4. 视觉与排版

- 四套主题：羊皮纸（默认，米白纸感 + 暖金强调）、浅色、深色、夜间护眼；未保存过主题时跟随系统深色偏好。
  正文面板（终端界面）统一深蓝底 `#0a0e27` / `#9cc2ff`，虚构语言用衬线栈单独排版。
- 中文正文：首行缩进 2em、段间距 0、两端对齐、`line-break: strict`、`text-spacing-trim: trim-start`、
  默认 20px / 行高 1.8（窄屏 18px）；单栏正文最大 38em；字号五档、行距三档、宋体/黑体两套系统字体栈。
- **中文段式两档**（阅读设置「中文段式」，只作用于中文栏）：
  - `常规段落`（默认）：首行缩进 2em、段间距 0，即上面的中文排版；
  - `一句一行`：按句断开、一句一行、取消首行缩进、段间留白，接近中文网文阅读习惯。
    实现方式是 `reader.js` 在每句终止符号后插入 `.sentence-gap`（`display: block` 的空 `span`），
    内联样式（说话人颜色、加粗、虚构语言字体）全部保留；切回常规时把这些标记删掉，
    正文 DOM 与构建产物保持一致，分页模式下会重新分列。
- **控件是一套「胶囊」语言**：顶栏三枚胶囊（目录页 / 章节目录 / 阅读设置）＋一枚实心强调胶囊（语言），
  底栏三段式胶囊，设置面板的分组选项也是胶囊（选中态实心填充）；
  统一 38–46px 高度、8–14px 间距、悬停描边+外发光、按下位移 1px，`prefers-reduced-motion` 下关闭位移与过渡。
  窄屏把按钮内边距、字号收紧，避免挤压换行。
- **章末不放导航**：正文流末尾没有「上一章 / 返回目录 / 下一章」胶囊，跳章只由底栏那对按钮承担；
  跨章跳转的目标挂在 `<link rel="prev">` / `<link rel="next">` 上（首章的 prev、末章的 next 回落目录页），
  `reader.js` 在到章首/章末继续按「上一屏 / 下一屏」时读它。
- 无障碍：焦点可见、跳转链接、`role="dialog"` + 焦点圈定与归还、`aria-pressed`/`aria-expanded`、
  `prefers-reduced-motion`、打印样式（隐藏控件、解除分页裁切、只打印当前显示的语言）。
- 无 JS 时：中文单栏完整可读，交互控件不出现（`.js-only` 与 `html:not([data-js])` 规则）。
- 零外部依赖：不用 CDN、不用 webfont、不用框架，图标都是字符或纯 CSS。

## 5. 集成修正

视觉模型分多次调用产出这些文件（网关 120 秒超时，单次输出必须够小），段落之间存在接口不一致。
组装前做了下列**最小修正**，代码里都带 `[集成修正]` 注释：

| 位置 | 问题 | 处理 |
| --- | --- | --- |
| `reader.js` 的 `qs()` | 第 1 段按裸 id 实现（`getElementById`），第 2、3 段按 CSS 选择器调用（`'#reader-main'`），结果第 2 段整段空转：双语分栏、点击翻页、同步滚动全不生效 | `qs()` 同时接受 `'#id'` 与裸 id（任务书已同步补充该约定） |
| `reader.js` 的同步判定 | 第 1 段把 `sync` 规范化成布尔值，第 2 段只认字符串 `'on'`，同步滚动永不生效 | 两种取值都认（与第 3 段一致） |
| `reader.js` 分栏阈值 | 原判据按每栏 34 字折算（`68F`），1366/1440 宽的常见桌面窗口会落到标签页，与「宽屏左右分栏」的要求不符 | 放宽到每栏 30 字（`60F`） |
| `chapter.html` | 正文两栏外面多套了一层 `<div class="reader">`，两栏不是 `#reader-main` 的直接子元素，分栏用的 `grid-template-columns` / `grid-column` 全部落空（两栏上下堆叠） | 去掉该层 |
| `chapter.html` 顶栏按钮 | 第 3 段 CSS 按「长/短两套文案」（`.reader-control__label` / `.reader-control__short`）写好了窄屏规则，模板里却只有一串纯文本，390px 下顶栏横向溢出、「阅读设置」被裁 | 按 CSS 的预期补上两组文案 |
| `overrides.css` | 第 3 段用 `html.js`（class）判断「JS 可用」，核心 JS 按契约写的是 `data-js` 属性，`#lang-tabs` / `#bottombar` 永远不显示 | 单独一份 `overrides.css` 用属性选择器补上 |
| `overrides.css` | 定高多列容器里 `.chapter-content { height: 100% }` 正好等于「一列高」，正文只占第 1 列、其余溢出到后续列，紧跟其后的**章末导航被挤到第 2 列**（表现为「翻页模式下章末导航出现在正文中间」） | 改回 `height: auto` |

用户提出界面改进后追加的修正（同样带 `[集成修正]` / `[用户请求]` 注释）：

| 位置 | 问题 | 处理 |
| --- | --- | --- |
| `reader.js` 的 `measureLayout()` | 用 `#reader-main` 的实测尺寸判分栏：该元素在标签页/单栏下被 `max-width: 38em` 限宽、高度又是整篇正文的自然高度，量到的是「当前布局」而不是「可用空间」。窗口一旦变窄掉进标签页，就再也回不到分栏（**宽屏偶发显示成窄屏样式**） | 改为按视口可用宽（− 页边距、夹到 `76em + 32px`）与视口高（− 顶栏 − 底栏）判定 |
| `reader.js` 的 `measureLayout()` 提前返回 | 第 1 段在切到「中文/English」时会把 `data-dual-layout` 强制写回 `columns`，与模块内的 `layout` 变量可能不一致；只比 `next === layout` 会带着错误属性一起提前返回 | 属性与变量都对上才提前返回 |
| `reader.js` 的 `measureLayout()` 触发条件 | 只挂在 `ResizeObserver` 上：视口变化（浏览器缩放、iframe 被拉宽）或无头环境丢一次 RO 回调时，判据不重算，「由窄变宽恢复分栏」就不会发生 | 同时挂 `window.resize`，并加回归预设 `read-dual-recover`（手机框 390px 起、再拉宽到 1600px，必须恢复分栏） |
| `reader.js` 的同步滚动 | 对栏写入被推迟到 `requestAnimationFrame`；无帧环境（无头探针、后台标签页）里 rAF 迟迟不执行，对栏停在原位，看起来像「同步滚动没生效」 | 收到栏内滚动时**同步写入**对栏（对方产生的 scroll 事件由 `expected` 判定吃掉，不会回环），并去掉 `syncFrame`/`syncSource` |
| `reader.js` 的栏内 scroll 监听 | 分散挂在两栏元素上；无头环境下嵌套滚动容器的 scroll 事件常排进队列却轮不到渲染帧派发 | 改为在 `document` 捕获阶段集中接收两栏的 scroll |
| `reader.js` 的段式 | 新增 `paragraph` 设置（`standard` / `webnovel`），需要与 CSS、分页重排对齐 | 根元素写 `data-paragraph`，并加入第 3 段 `MutationObserver` 的属性白名单，切换后分页模式重新分列 |
| `reader.js` 的滚轮接管 | 终端面板带 `overscroll-behavior: contain`，指针在内部滚动区到边后浏览器不会接续整页；分栏时正文内滚动也滚不动上方的章标题区 | `main` 上挂 `wheel` 监听，按「内层滚动区 → 正文栏 → 整页」逐级接管，到边后显式滚动外层 |
| `chapter.html` 底栏 | 只有「上一屏/下一屏」，没有真正的跳章入口 | 底栏改为三段式（上一章 · 翻屏与进度 · 下一章），新增 `#btn-prev-chapter` / `#btn-next-chapter`，由 `build_site.py` 用 `{{PREV_CH_HREF}}` / `{{NEXT_CH_HREF}}` 与 `hidden` 填充 |
| `render_site_previews.py` 的滚动类动作（同步滚动、进度写盘） | 无头 + `--virtual-time-budget` 下滚动事件经常派发不到，探针会把「同步滚动/进度记忆没生效」误判成缺陷（同步滚动改前 5 次里假失败 3 次） | 动作脚本在设置 `scrollTop` / `window.scrollTo` 之后补派发一次 `scroll` 事件；被测的是页面「收到滚动后如何响应」，浏览器自身是否派发不在范围内 |

用户报告「移动端拖拽极其僵硬、无法正常滚动」后追加的修正：

| 位置 | 问题 | 处理 |
| --- | --- | --- |
| `overrides.css` 的 `.device-view` | 终端面板带 `overscroll-behavior: contain`，而面板在竖向上没有溢出：手指落在面板上往下拖，既不滚面板、也不会接续滚正文（**滚动整个被吃掉**）。桌面滚轮由 `reader.js` 显式接管，触摸没有对应接管。390px 手机上实测：面板上拖 300px，`window.scrollY` 位移 **0**；正文其它位置同样是 300px 拖拽能滚 285px | 面板改回 `overscroll-behavior: auto`，把 scroll chaining 交还浏览器（面板自己有余量时仍先滚面板，滚到头再接续整页）。修后同一手势位移 285px |
| `reader.js` 的触摸手势 | 翻页模式（`data-page-mode="paged"`）**没有任何触摸入口**：只能点左/右三分之一翻页，手机上本能地横向滑动却毫无反应，同样是「拖不动」 | 补横向滑动翻页：`touchstart`/`touchend` 记录起止点，横向位移 ≥48px 且 ≥纵向 1.2 倍才翻页；落在面板、链接、按钮等交互区时不接管（交给内部横向滚动）。纵向滑动不翻页 |
| `probe_site.py` | 上面两条都是「只在触摸设备上才出现」的问题，`--dump-dom` 几何探针看不见 | 加两条回归断言：`#pane-zh` 内 `<em>/<i>` 数必须为 0（中文不用斜体）、`.device-view` 的 `overscroll-behavior-y` 必须是 `auto` |

本轮改版后的第二轮视觉复核（图像模型逐图 + 像素测量，两路结论一致）又发现并修掉：

| 问题 | 处理 |
| --- | --- |
| 窄屏顶栏控件全挤在左侧，右侧空 86px（22%），而下方语言标签条却是居中的 | 顶栏改为 `justify-content: space-between`：品牌靠左、控件靠右（390px 下右侧留 12px） |

`overrides.css` 由 `build_site.py` 注入到每个页面 `<head>` 末尾；视觉模型的三份原始产出只做上面
列出的最小改动，其余保持原样，便于将来用同一份任务书重新生成后做 diff。
`overrides.css` 里的内容分三类：① 接口对齐；② 视觉复核修补；③ 用户请求的界面调整
（胶囊控件与间距、底栏上一章/下一章、「一句一行」段式），集中在文件末尾，便于逐块取舍。

## 7. 术语卡片

读者在正文里点到某个专业术语，弹出一张**简要介绍卡**：概念名、阅读门槛、一句话定义、
一个生活化比喻、可选的「先读」，以及通往完整教程的链接。**卡里不解释前后文关系**——
「这个概念在后面哪几章出现、各自起什么作用」属于情节层信息，读者在正文里只需要知道
「这个词是什么意思」，其余交给完整教程页。数据源是 [`pipeline/terms.json`](../pipeline/terms.json)，
43 个概念对应 `docs/explainer/` 的 43 篇科普文档。

### 7.1 为什么完整教程指向 GitHub 而不是站内页

「读完整教程」链到 `https://github.com/0xVanfer/snowmoon-zh-cn/blob/main/docs/explainer/<doc>`（新标签页打开）。
理由是那 43 篇是 **Markdown + LaTeX**，GitHub 原生渲染表格、行内/块公式、标题大纲与相对链接；
站内自研渲染器要覆盖 89 个 LaTeX 命令、884 行表格（其中 411 行含行内公式或加粗）与 9 类块级构造，
且任务书硬约束第 1 条禁止引入 npm 包与 webfont，vendor KaTeX 直接违规。

代价是**教程页跳不回原文**——文档里的 `（第1章，chapter-01.md:9）` 在 GitHub 上是死文本。
缓解办法是把「跳回原文」放在卡片上（章号 chip 直达具体段落），而完整教程那一层只负责讲透。

落地页是 `terms.json` 派生字段（`terms.page_url()`），将来若要改成本地生成页，只改这一处。

### 7.2 标注：别名必须实测，不能从文档标题推导

`docs/explainer` 的 H1 是**描述性标签**，不是书里的实际用词。实测：

| 文档标题 | 全书命中 | 书里实际写的 |
| --- | --- | --- |
| 对抗补丁 | 0 | 对抗攻击 |
| 熵与信息论 | 0 | 熵 |
| 异或与 Nim 和 | 0 | 异或 |
| 二项式分布 | 0 | 二项式公式 |
| 混淆电路与两方计算 | 0 | 混淆电路 / 两方混淆电路 |

所以 `terms.json` 的 `aliases_zh` 全部由全书命中统计得出，共 77 条。

两个概念 `mark: "none"`（`sybil-and-collusion` 女巫攻击、`expectation-and-conflict` 期望值与利益冲突）：
小说通篇只描述现象、从未给出这两个词，正文里没有可标的点。这两个概念只能从 GitHub 的概念总表进入，
`validate_terms.py` 会把它们单列出来——是数据事实，不该被当成缺陷悄悄吞掉。

**别名表必须全局唯一且全局最长优先**（`terms.alias_matcher`），不能每个概念各编各的：
「零知识」属概念 4 而「零知识抵押」属概念 5，分表匹配会让 4 抢走 5 的词；
「签名」属概念 6 而「基于哈希的签名」属概念 8，反向同理。`mark: "first"` 时同一概念每章只标第一处。

标注只切文本节点，**绝不碰标签与属性**；译注气泡内部整体跳过（否则出现嵌套可点区域）。

### 7.3 卡片必须一屏装得下，不靠卡内滚动

读者报过「卡太长时内部滚不动」。原因不是 `overflow` 写错了，而是**触屏上滚动与开合冲突**：
指针从词移向卡会先触发词的 `mouseleave`，160ms 后卡片就被收掉了，根本来不及划。

所以改成**从结构上保证装得下**，而不是靠滚动兜底：

- 卡片固定 4 段（概念名+门槛 / 定义 / 比喻 / 链接），「先读」最多再占 1 行；
- 章号列表、权重标签、章说明、「后面还会怎么用」一律**不进正文卡**（它们是前后文关系，
  且一张章号列表能堆到二十多行）；
- `validate_terms.py` 按**最坏情况**估算高度并卡死：最窄常见视口 390px × 最大字号 24px
  → 卡片内容宽约 344px、字号 0.82em、每行 17 个汉字、行高约 33.5px；
  可用高度（844 − 顶栏 48 − 底栏 56 − 安全区 34）约 706px，预算取 560px。
  实测 43 张卡是 264–407px、中位 364px，全部远在预算内——这个阈值平时不拦人，
  作用是**将来有人往气泡里加内容时当场拦住**。

字段长度上限同步收紧（`one_liner` ≤52 字、`analogy` ≤70 字），闸门按编号槽位之外的内容一并检查。

### 7.4 深链：进度记忆会覆盖 fragment

卡片上的章号 chip 指向 `chapter-NN.html#cNN-sNNNN`。块级 `id` 由 `build_site.render_blocks`
挂在**中文栏**（英文栏保持原书纯净，且中英同名 id 会让 fragment 归属不明）。

浏览器自带的 fragment 滚动会被进度记忆覆盖——`restoreVisible()` 一跑就把 localStorage 里的旧位置
写回去，读者点「第 6 章」落回上次读的地方。所以 `reader.js` 里带 `#cNN-sNNNN` 进入时整段跳过进度恢复，
改成滚到锚点并闪一下（`.is-deeplink`）。

两处都要跳过，缺一不可：分栏模块的 `restoreVisible()`，以及进度/存档模块 `relayout()` 里
按 `snapshots` 写回位置那次。后者由图片加载、字体就绪、表格分列反复触发，每次都会把读者从落点
拽回旧进度。`api.deepLink` 是两边唯一的联络方式，入口 `applyDeepLink()` 就地调用、
不跨 IIFE——早年的写法把调用点放在另一个 IIFE 里，运行时报 `ReferenceError`，
`enhancePages()` 当场中断，深链**从来没生效过**，而浏览器自带的 fragment 滚动把症状掩盖住了。

落位先同步做一次、再等两帧校正：只等 rAF 的话，慢设备上会「先停在旧位置一下才跳」，
无头环境里则可能永远等不到那一帧。

### 7.5 定位与数据来源

- `build_markdown.py` 额外产出 `pipeline/line_index.json`（{章: {片段 id: [起行, 止行]}}，4150 条），
  用来把 `docs/explainer` 里的 `chapter-NN.md:行号` 换算成片段 id。
  **产物字节一个都不动**——那些引用是按当前行号写死的，而在 `parts` 里插标记会让 `clean_ws()` 之后
  所有后续块行号前移，且错位后每行仍然「存在且非空」，逐条核对也查不出来。
  验证方式是重建后 `git diff --exit-code -- book/` 必须干净。
- `pipeline/terms.py` 是数据层（装载 / 标注 / 锚点解析），`build_site` 与 `validate_terms` 共用，
  避免「同一规则两套实现」。
- 完整教程链接带 `target="_blank" rel="noopener"`：站点从未卸载，读者关掉标签页即回到原位，
  比同页跳转 + 滚动恢复更彻底。

### 7.6 闸门

`pipeline/validate_terms.py` 跑在 `build_site` **之后**，校验最终产物而不只是数据自洽：
概念 ↔ 文档双射、概念名与文档 H1 一致、card 长度与禁用字符、别名全局唯一、prereq 存在且无环、
`chapters[].ch` 等于文档实际引用的章集合、每个引用解析到的片段在译文里存在、
产物里逐页「触发点 ↔ 卡片」一一对应、章号链接指向的 id 真实存在、教程链接是生产地址、
`.term-store` 容器没带 `hidden`。

三条无头环境跑不到的行为改用静态守卫检查：`restoreVisible()` 的深链跳过、
`enhancePages()` 里 `applyDeepLink()` 的**调用点**（只查函数名会漏掉「定义了但没人叫」）、
`addSentenceGaps()` 跳过 `.term` 内部。

`terms.json` 缺失或 `concepts` 为空 = 功能关闭（kill switch）：产物里不出现任何 `.term` 标注，
站点与加这个功能之前一致，闸门则打印「跳过 N 项」并**单列**，不与「通过」混在一起。

反向测试：14 项逐条注入故障（card 超长 / 含公式符号 / 别名重复 / prereq 悬空 / prereq 成环 /
章号与文档不符 / 概念名不符 / 触发点无卡片 / 卡片无触发点 / 全书别名失效 / 章号死 id /
卡片池带 hidden / 教程链接非生产地址 / 三处 reader.js 守卫被删）全部能让闸门变红。
