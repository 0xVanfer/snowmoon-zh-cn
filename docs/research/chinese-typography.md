## 1. 标点符号

### 1.1 总原则

- **中文正文里只用中文全角标点。** CY/T 154—2017 §5.1.1–§5.9.1 逐项规定「中文句号通常为『。』，为全角字符；英文句号为『.』，为半角字符」，逗号、分号、冒号、引号、圆括号同理。GB/T 15834—2011 适用于「汉语的书面语（包括汉语和外语混合排版时的汉语部分）」。
- **西文/数字段落的内部用西文标点。** 中文句子里夹用的英文句子，其内部标点用英文标点（CY/T 154 §5.1.2.2、§5.4.2.1、§5.6.2.1、§5.7.2.2）。
- **不要用全角 ASCII 区段字符。** clreq 明确：过去为对齐而使用「全角 ASCII 字符」，现今「文本储存时，应避免使用该区段的拉丁字母及数字字符」。

### 1.2 逐个符号的结论

| 符号 | 结论（该怎么做） | 依据 |
| --- | --- | --- |
| 句号 `。` | 陈述句末用全角 `。`；中文陈述句里夹英文单词/句子，整句仍以 `。` 收尾 | CY/T 154 §5.1.2.1–§5.1.2.2 |
| 逗号 `，` | 句内一般停顿用 `，`；只用于句内，不用于句末；不要一逗到底 | 《差错认定细则》第 27、28 条 |
| 顿号 `、` | 并列词语/词组之间的停顿；层级是 顿号 < 逗号 < 分号 < 句号 | 《差错认定细则》第 29、30 条 |
| 分号 `；` | 只用于复句内并列分句之间；**不用于普通单句、并列词语、非第一层分句** | 《差错认定细则》第 29 条 |
| 冒号 `：` | 提示性话语之后提起下文；**「某某说」插在引文中间时，「说」后用逗号，不能用冒号** | 《差错认定细则》第 33 条(一) |
| 问号 `？` | 只用于疑问/反问/设问句末；有「谁、哪、什么、怎么、是……还是」但整体是陈述句时用句号 | 《差错认定细则》第 31 条 |
| 叹号 `！` | 只用于语气强烈的祈使/陈述/反问句末；语气舒缓的用句号 | 《差错认定细则》第 32 条 |
| 引号 | **横排简体一律用弯引号 `“ ”`（先双后单）**；引文中再引，外层双、内层单 | clreq 5.x 引号节（中国大陆「采用先双、后单的引号体例，弯引号用于横排、直角引号用于直排」）；GB/T 15834—2011 |
| 「 」 | **本项目不用。** 直角引号在中国大陆是直排形式（简体）/ 台湾地区横排形式；横排简体用它会与全书体例冲突 | clreq 引号节 |
| 书名号 `《》` | 书名、篇名、歌曲名、影剧名、文件名都用双书名号 `《》`；书名号内再套书名号用单书名号 `〈〉` | clreq 引 GB/T 15834—2011（「无论书名、篇章名都应该使用双书名号」） |
| 括号 `（）` | 中文注释用全角圆括号；夹注的英文段落**内部**的括号用英文半角括号 | CY/T 154 §5.9.2.1–§5.9.2.2 |
| 破折号 `——` | 占两个汉字宽；中文里用中文破折号，英文部分内部用英文破折号；**不得因分行而断开**（视为一体） | clreq 破折号节；clreq 6.1.2.1 |
| 省略号 `……` | 占两个汉字宽、六个点，写作两个连续 `…`（U+2026），**不写 `...`、`。。。`**；不得拆行；两个省略号连用时占四个汉字位并单独占一行 | clreq 省略号节（并引 GB/T 15834—2011 5.1.5） |
| 间隔号 `·` | 用 **U+00B7 MIDDLE DOT**；用于人名内部分隔、书名号内篇/章/卷分隔、月日专名分隔。**不用 `•`(U+2022)、`・`(U+30FB)、`．`、`‧`** | clreq 间隔号节（「建议使用 U+00B7 MIDDLE DOT」，「U+30FB 来自日文 JIS 编码，并非中文编码，不建议使用」） |
| 连接号 / 分隔号 | 短横线 `–`（半字）、一字线 `—`、浪纹线 `～`；数值范围用 `～` 或 `—`。分隔号 `/` 用于诗行、节拍、相关文字分隔，不能出现在行尾；两者都不拆行 | clreq 连接号·分隔号节；clreq 6.1.1；GB/T 15835—2011 §5.1.3 |
| 着重号 | 横排标在文字下方；**本项目不用**（Markdown 无法表达，改用加粗） | clreq 着重号节 |

### 1.3 禁止出现的半角标点误用（本项目的红线）

1. 中文句子里不得出现 `,` `.` `!` `?` `:` `;` `(` `)` `"` `'` 充当标点。这些只允许出现在**英文片段内部**或**代码/URL**中。
2. 不得用 `.` 代替 `。`，不得用 `,` 代替 `，`，不得用 `...` 代替 `……`。
3. 不得混用直角引号与弯引号（例如同一章内既有 `“”` 又有 `「」`）。
4. 不得用 `•`、`・`、`.`（下脚点）充当间隔号；下脚点只用于**英文**人名的缩略（A.G.普瑞斯顿），中文部分人名缩略用 `·`（安东尼·G.普瑞斯顿）——CY/T 154 §6.1–§6.2。
5. 冒号与比号 `∶` 不得互混（《差错认定细则》第 33 条(五)）。

### 1.4 标点重复与叠用

- 疑问与感叹同时强烈时，**用 `？！`（问号在前）**，不用 `！？`；占一个字位置。
- 问号、叹号可叠用表示语气加重，**最多三个**（`!!!`、`???`）；两个叠用占一个字位置，三个占两个字位置。依据：clreq 引 GB/T 15834—2011 叹问号条的延伸用法。
- 本项目补充：叠用仅用于对白，叙述文字一律单用；禁止 `。。`、`，，`、超过三个的 `！！！`。

### 1.5 行首行尾禁则（排版层）

clreq 6.1.1「基本处理」：顿号、逗号、分号、冒号、句号、叹号、问号、结束引号、结束括号、结束书名号、连接号、间隔号、分隔号**不能出现在一行开头**；开始引号、开始括号、开始书名号**不能出现在一行结尾**。「严格处理」再加：破折号、省略号不能出现在行首。Markdown 源文件无法控制这点，**必须在渲染层解决**（`line-break: strict`）；处理顺序「先挤压、后推出」属排版引擎职责，本项目不做手工断行。

## 2. 中西文混排

### 2.1 中英文之间要不要加空格：主流结论与两种流派

**标准结论：不强制，只要求统一。** CY/T 154—2017 §8.1 原文：

> 中文文本中夹用英文词句时，应根据所选用的中英文字体、字符间距以及排版的视觉效果决定英文词句与中文文字之间是否留有空格间距。如留空格，应保证体例的统一。

- **加空格派**：以 [中文文案排版指北](https://github.com/sparanoid/chinese-copywriting-guidelines) / pangu.js 为代表，主张「中文与英文之间、中文与数字之间加一个空格」。
- **不加空格派**：多数传统出版社不在源文本里打空格，而由排版软件的字距（clreq 直排一节要求「汉字与西文字母、阿拉伯数字间使用不多于四分之一个汉字宽的字距或空白」）处理——即间隙是**排版引擎**的事，不是字符的事。
- **本项目决策：统一加 1 个半角空格。** 理由：Markdown 文本层可见、可用脚本检查、复制到任何渲染器都不丢；符合 CY/T 154「如留空格，应保证体例的统一」。该加：`他是 Snowmoon 的守望者。`、`共 32 章`；**不该加**：英文与中文标点之间（CY/T 154 §8.2）→ `……的守望者 Snowmoon。`。产品名/术语的官方写法优先（如 `Snowmoon` 本身不拆）。

### 2.2 数字与单位、百分比

- 量值与单位符号之间**留一个空格**：`5 km`、`30 kg`、`3.4 mm`（CY/T 154 §12.2.2 示例「3.4 mm」；「当单位符号位于数值之后且需要留有空隙时，应按英文排版规则留空」）。
- **不留空**的：百分号、千分号、度数符号紧贴其前的数字（`50%`、`36.5℃`），且不可换行断开（clreq 6.1.2.2）。
- 数字采用**半角**形式，字体与文中英文一致（CY/T 154 §12.1.1）。
- 四位以上整数/小数的分节：可用「千分空」或「千分撇」，**全书统一**（CY/T 154 §12.1.2；GB/T 15835—2011 §5.1.1）。本项目文学文本**采用千分空**（`55 235`），避免千分撇的 `,` 与中文逗号混淆。

### 2.3 英文缩写、代码与技术名词

- 缩略语首现：`中文全称（English Full Name, ABBR）`。CY/T 154 §5.9.2.2 原文示例：`脱氧核糖核酸（deoxyribonucleic acid, DNA）`。
- 英文普通单词/词组在中文句中，无论位置，**首字母一律小写**（CY/T 154 §7.1）；首字母必须大写的专名保留大写（§7.2）；**完整英文句子首词首字母保留大写**（§7.3）。
- 代码、变量、文件名、URL：用行内代码 `` ` `` 包裹，内部一律西文标点，且不在其中做中文空格处理。

### 2.4 专有名词首现夹注原文

- 格式：`中文译名（原文）`，括号用**中文全角圆括号**。CY/T 154 §5.9.2.1 示例：`罗杰·威廉斯（Roger Williams, 1946－）`。
- 本书做法：虚构专名与真实地名/人名**均只在首次出现时夹注**，并登记进术语表（见 §4.4）。
- 英文**书名**不用中文书名号，改用**斜体**（CY/T 154 §10.1）；英文**文章标题**用正体＋中文引号（§10.2）。
- 英文书名中的副书名用冒号，文章副标题用英文破折号（CY/T 154 §10.3）。

### 2.5 斜体与加粗在中文里的可读性

- **中文不用斜体。** 汉字是方正字形，倾斜后辨识度下降；且多数中文字体没有真正的斜体字面，浏览器/渲染器会用合成倾斜（机械 slant），效果更差。
- **本项目规定**：中文强调一律用 `**加粗**`；斜体只用于**英文书名、外语词**。加粗只用于术语首现、图注标签、表头，不用于整句或整段。

## 3. 数字与单位

### 3.1 阿拉伯数字 vs 汉字数字（GB/T 15835—2011）

| 场合 | 用哪种 | 依据 |
| --- | --- | --- |
| 计量（长度、质量、温度、数量值） | 阿拉伯数字 | §4.1.1 |
| 编号（电话、编号、型号、章节号） | 阿拉伯数字 | §4.1.2 |
| 已定型含阿拉伯数字的词（3G 手机、维生素 B12） | 阿拉伯数字 | §4.1.3 |
| 非公历纪年（干支、农历、历史朝代） | 汉字数字 | §4.2.1 |
| **概数**（三四个月、一二十个、五六十年前、二十几） | 汉字数字 | §4.2.2 |
| 已定型含汉字数字的词（成语、星期五、四书五经、七上八下） | 汉字数字 | §4.2.3 |
| 年份 | 阿拉伯数字，**不简写**（「1990 年」不写「90 年」） | §5.1.4 |
| 两种均可时 | 选一种并遵守「同类别同形式」 | §4.3 |

其他硬性规则：

- 纯小数必须写出前导 0：`0.46`，不写 `.46`（§5.1.2）。
- 概数的两个数字之间**不用顿号**：`二三米`、`四十五六岁`（§5.2.1）。
- 避免相邻阿拉伯数字造成歧义：写 `高三（2）班`，不写 `高32班`（§4.3 示例 4）。
- 一般数值**不同时使用**阿拉伯数字与汉字数字；只有「万」「亿」可保留汉字（`10亿零817万5288人`）（§5.3）。
- 「0」作计量写「零」，作编号写「〇」（`二〇二四`、`二〇一二`）（§5.2.5）。
- 大写汉字数字（壹贰叁）只用于法律、财务文书（§5.2.4）——本小说不用。

### 3.2 数值范围

用浪纹线 `～` 或一字线 `—`；前后单位相同时可省略一个，**但省略会造成歧义时不能省**（GB/T 15835—2011 §5.1.3）：

- 写 `15%～30%`，不写 `15～30%`
- 写 `9亿～16亿`，不写 `9—16亿`
- 写 `13万元～17万元`，不写 `13～17万元`
- 写 `100—150 kg`（单位相同，可省前一个）

### 3.3 时间与日期

- 年月日按口语自然顺序：`2008年8月8日`；用 `-` 替代是 GB/T 7408—2005 扩展格式（`2008-08-08`），**年月日不完整时不能用 `-`**（`8月8日` 不写 `8-8`，`2008年8月` 不写 `2008-8`）（§5.1.4）。
- 时分秒：`15时40分`、`14时12分36秒`，或 GB/T 7408 扩展格式 `15:40`、`14:12:36`（§5.1.5）。**本项目叙事文字统一用「×时×分」**，只有在表现屏幕/仪表文本时才用 `15:40`。
- 含月日的专名用间隔号：`“3·15”消费者权益日`、`“一·二八”事变`（§5.1.6、§5.2.3）。
  - ⚠️ 注意：GB/T 15835 的转载文本里这两个示例用的是 U+2022 `•`，而 clreq 明确建议间隔号用 U+00B7 `·`。**本项目统一用 `·`（U+00B7）**，两种字符的可核实现状已记录，未经官方印本标准原件复核（**未核实**）。

### 3.4 度量衡换算（英里/英尺/磅 → 公里/米/公斤）

- **规范立场**：我国法定计量单位以国际单位制为基础；《图书质量管理规定》的编校差错计算方法把「使用计量单位不符合国家标准《量和单位》（GB 3100～3102—1993）的中文名称」按每处 1 个差错计。英制单位（英里、英尺、英寸、磅、加仑、华氏度）**不是**我国法定计量单位，正式出版物不应作为计量单位使用。
- **本项目处理原则**（叙事文本的可执行做法）：
  1. 叙述与测量一律**换算为公制**，并取符合语感的近似值。
  2. 换算系数（通用近似值，**未逐条核对标准换算表**）：1 英里 ≈ 1.6 公里；1 英尺 ≈ 0.3 米；1 英寸 ≈ 2.5 厘米；1 磅 ≈ 0.45 公斤；1 加仑 ≈ 3.8 升；℉→℃：`C = (F − 32) × 5 / 9`。
  3. 需要保留异域/时代语感时，用「约」模糊化，或首现处夹注原文：`三英里（约 4.8 公里）`。
  4. 华氏温度在对话里可保留 `℉` 但首现夹注摄氏度，之后统一。
- **货币**：用汉字单位「美元 / 英镑 / 便士」，金额用阿拉伯数字；不用 `$`、`£` 符号与中文混排（clreq 6.1.2.2 虽允许货币符号，但与「中文正文用中文」的总原则冲突）。首现可夹注原文：`二十美元（$20）`。

### 3.5 参考文献（如译文需要）

GB/T 7714—2015 规定顺序编码制与著者-出版年制两种体系，正文中以上标方括号标注序号。本译文如需列源文献，按顺序编码制著录；具体条款号**未核实**（仅取到出版社转载件）。

## 4. 人名地名译写与虚构专名

### 4.1 权威依据

- **《世界人名翻译大辞典》**：新华通讯社译名室主编，中国对外翻译出版公司，1993 年 10 月初版、2007 年修订版（ISBN 9787500107996）。该书版权页/简介自述其作用为「对于统一规范外国人名的译名工作……成为社会政治经济生活中具有一定权威性的常用工具书」。来源：[知网工具书条目](https://mall.cnki.net/reference/detail_r200807102.html)、[豆瓣版本页](https://book.douban.com/subject/2149292/)。
  - 说明：这是**行业事实标准**（推荐性国标未覆盖外国人名汉字译写），不是国家标准。写作时不要称其为「国标」。
- **《世界地名翻译大辞典》/ 外国地名译名手册**同属新华社译名室—中国对外翻译出版公司体系，与地名主管部门的译写导则配套使用。
- **GB/T 17693《外语地名汉字译写导则》**系列：全国地名标准化技术委员会提出并归口，**已发布 12 个语种**的分册（依据：[国家标准技术审评中心标准云课课程简介](http://cc.sacinfo.org.cn/course?id=8a6dd87172cbeab00172e47e3f72035e)）。各分册的「约定俗成、同名同译、一名一译」等具体条文内容**未核实**（未取到分册全文）。
- **GB/T 28039—2011《中国人名汉语拼音字母拼写规则》**：正式汉语人名姓和名分写、姓在前名在后、姓名之间用空格、复姓连写、姓和名的开头字母大写；适用于编辑出版。来源：[全文转载](http://www.jzp.edu.cn/yywz/2017/0526/c1040a7992/page.htm)。
- **人名缩略**：中文部分后用中圆点 `·`，英文部分后用下脚点 `.`（CY/T 154 §6.1–§6.2，示例 `安东尼·G.普瑞斯顿`、`A.G.普瑞斯顿`）。

### 4.2 音译用字规范

- **避免生僻字**：不用输入法难打、读者读不出的字（这类字在 HTML 字体回退时还容易变成豆腐块）。
- **避免歧义与不雅谐音**，避免译名与常用词、贬义词同形。
- **约定俗成优先**：已有通行译名（既有中译本、官方译名）不改，哪怕「不标准」；具体条文**未核实**。
- **一名一译、同名同译**；不同原文但同名者用不同汉字区分。
- 用字偏好：优先人名常用译字；避免用「爷、妈、死、坟」等表意过强的字做纯音节。

### 4.3 虚构专名的处理策略

**决策树（按顺序判断）：**

1. **已有通行译名**（涉及既有作品/现实人物地名）→ 沿用，不重译。
2. **构词可解 / 有实义**（`Snowmoon` = snow + moon；`Northgate` = 北门）→ **意译优先**，并保证全文一致。
3. **纯音响自造词 / conlang 术语**（无实义、无形态线索）→ **音译**，首现处夹注原文，登记术语表。
4. **半音半意**（前缀是实义词 + 后缀是不可解音节）→ 半音半意，如 `X-` → 「X 氏」。
5. **称号 / 种族名 / 器物名** → 倾向意译，保持中文读者的语义直觉。

**硬性要求：**

- 首现处一律夹注原文：`雪月（Snowmoon）`，格式遵循 CY/T 154 §5.9.2.1 的「中文（原文）」模式。
- 维护 `translations/zh/glossary.md`（术语、首现章节、原文、词性、音标/读音、译法依据）。**术语表是唯一事实源**，正文与图注、表注必须一致。
- 押韵/谐音/双关造成的语义损失，用译者注说明，**不硬译**。
- 学术讨论（策略层面的参考）：吴明阳《奇幻小说中的专有名词翻译研究》，西安外国语大学硕士学位论文，2017（以《哈利·波特》中译本为对象讨论奇幻专名的翻译策略与技巧），[CNKI 条目](https://cdmd.cnki.com.cn/Article/CDMD-10724-1017821474.htm)。
- **声明**：虚构专名的具体译法属译者裁量，目前**没有**适用的国家标准或行业标准；不要在本项目中援引不存在的「译名国标」。

## 5. 正文以外的元素

### 5.1 图表标题与图注

- **图题在图下方，表题在表上方**——这是出版通行惯例。GB/T 15834—2011 与 clreq 都不规定图表格式，本项目不援引国标条款（图题位置的标准依据**未核实**）。
- 图题编号用阿拉伯数字并与正文一致：`图 3-2　Snowmoon 的潮汐周期`。编号与标题之间用一个全角空格（U+3000）分隔。
- **图题不加句末标点**；图注若为完整句子，句内正常用标点、末尾可用句号。
- 图注中凡引用专名，格式与正文一致：`图 3-2　雪月（Snowmoon）的潮汐周期`。
- SVG 插图内的文字同样受本规范约束（全角标点、中西文空格一致），并**不得只靠颜色**传达信息（见 §5.5）。

### 5.2 表格文字

- 表头加粗；单元格内**不加句末标点**（除非单元格里是完整句子）。
- 单位写在表头：`距离 / km`、`质量 / kg`，不要在每个数字后重复单位。
- 表格内数值用阿拉伯数字（GB/T 15835—2011 §4.1.1）。
- 表格内文字左对齐、数字右对齐；Markdown 表格用 `:---` / `---:` 对齐语法。
- 需要合并单元格时只能用 HTML `<table>`；GitHub 会保留 `colspan` / `rowspan`（在属性白名单内，见 §6.1），但 GFM 表格语法本身不支持合并。

### 5.3 对话、说话人标注

- **一段话一个 `“……”`，独立成段，段间空行。** 不把多轮对话合并进同一段。
- 说话人在前，用冒号：`她说：“……”`
- 说话人在中间，用逗号，**不能用冒号**：`“唔。”老张一面听，一面应，一面伸手过来说，“你给我吧。”`（《差错认定细则》第 33 条(一)）
- 不说话人、只连续对白的，每条对白单独成段，依赖上下文辨认说话人。
- 引文末尾标点：完整引用时句末点号在引号内；作为句子成分的局部引用，点号在引号外（《差错认定细则》「引文末尾标点位置混乱」条）。
- 省略号、破折号前后**不再加其他点号**（《差错认定细则》「省略号前后的标点均应删去」条）。
- 破折号也可标示对话（CY/T 154 §5.10.2.3），但**同一段会话中不能中文破折号与英文破折号混用**；本项目统一用中文引号的对白形式，破折号只作句内用途。

### 5.4 内心独白、书信/消息/屏幕文本

| 元素 | 本项目做法 | 理由 |
| --- | --- | --- |
| 内心独白 | **不加引号**，独立成段，用叙述标记（「他想」「她心里」）区分；需要视觉分区时用 Markdown 引用块 `>` | 中文没有通用的独白专用标点；引用块在 Markdown/HTML 都能稳定渲染 |
| 书信 | 引用块 `>`；抬头、正文、落款各成段；落款需要右对齐时用 `<p align="right">` | `align` 属性在 GitHub 白名单内（§6.1） |
| 手机消息 / 屏幕文本 | 引用块或围栏代码块 ```` ``` ````；多条消息按时间顺序各成一段、加说话人标签 | 代码块保留原样、不参与中西文空格处理 |
| 计算机/终端输出 | 围栏代码块，内部一律 ASCII 标点 | 避免中文标点混入 |

### 5.5 颜色标注的可用性与无障碍

- 原著用颜色区分说话人/情绪。**颜色不能作为唯一的信息载体**：W3C WCAG 2.1 成功准则 1.4.1（Level A）原文：

  > Color is not used as the only visual means of conveying information, indicating an action, prompting a response, or distinguishing a visual element.

  （[Understanding SC 1.4.1](https://www.w3.org/WAI/WCAG21/Understanding/use-of-color.html)）
- 若在 HTML 单页中保留颜色，正文颜色与背景的对比度**至少 4.5:1**，大字号至少 **3:1**（[SC 1.4.3 Contrast (Minimum), Level AA](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum.html)）。
- 红绿色觉异常约占男性 1/12（8%）、女性 1/200（[Colour Blind Awareness](https://www.colourblindawareness.org/colour-blindness/)）——「红=某人、绿=另一人」的方案对这部分读者完全失效。
- **本项目结论**：
  1. **正文不使用颜色区分说话人**；改用说话人标签（人名/「他」）、段落顺序、引号层级等冗余线索。
  2. 颜色只能作为**冗余装饰**，且必须与文字/符号/线型标签同时出现（例如图例「─●─ 甲（实线）」）。
  3. 对话标注色若必须保留，必须同时给出非颜色标签，并在 HTML 单页里保证对比度达标。
  4. Markdown 源里**不写颜色**（GitHub 会剥离，见 §6.1）；颜色只允许出现在自建渲染管线的 CSS 里。

## 6. Markdown 的限制与对策

### 6.1 内联 HTML 的边界（GitHub 会剥离 style）

GitHub 的渲染管线会主动清洗 HTML。`github/markup` 的 README 原文：

> The HTML is sanitized, aggressively removing things that could harm you and your kin—such as `script` tags, inline-styles, and `class` or `id` attributes.

（[github/markup README](https://github.com/github/markup)）

`html-pipeline` 的 `SanitizationFilter` 白名单（[源码](https://github.com/github/html-pipeline/blob/master/lib/html/pipeline/sanitization_filter.rb)）：

- **允许的元素**：`h1`–`h8`、`br`、`b`、`i`、`strong`、`em`、`a`、`pre`、`code`、`img`、`tt`、`div`、`ins`、`del`、`sup`、`sub`、`p`、`ol`、`ul`、`table`、`thead`、`tbody`、`tfoot`、`blockquote`、`dl`、`dt`、`dd`、`kbd`、`q`、`samp`、`var`、`hr`、`ruby`、`rt`、`rp`、`li`、`tr`、`td`、`th`、`s`、`strike`、`summary`、`details`。
- **不允许的元素**：`span`、`font`、`style`、`script`、`iframe`、`section`、`input`、`button`、`figure`、`figcaption`。→ `<span style="color:red">文本</span>` 标签被删、文字保留，**颜色丢失**。
- **允许的属性**（`:all`）：`align`、`width`、`height`、`colspan`、`rowspan`、`title`、`start`、`lang`、`dir` 等；`a` 只留 `href`，`img` 只留 `src`/`longdesc`。**被剥离**：`style`、`class`、`id`。
- 用自建管线渲染（本项目计划的 HTML 单页）时以上限制不适用，颜色与缩进可用 CSS 实现。

**可用的 HTML 逃生口**（GitHub 上仍有效）：`<p align="center">`、`<p align="right">`、`<td colspan="2">`、`<img width="520">`、`<sup>`/`<sub>`、`<ruby>`（注音）、`<details>`/`<summary>`。

### 6.2 段落分隔与硬换行

- **段落之间空一行。** CommonMark 中连续的行会合并为同一段（软换行）。
- 需要段内强制换行时，行尾加**两个空格**或反斜杠 `\`（CommonMark 6.7 Hard line breaks）。**本项目正文不使用硬换行**——中文小说每段独立成段即可。
- 行尾两个以上空格在段落**末尾**会被剥离（CommonMark 示例 226），不要用它做视觉间距。

### 6.3 避免数字+句点被误判为有序列表（重点）

CommonMark 5.2 原文：

> An ordered list marker is a sequence of 1–9 arabic digits (0-9), followed by either a `.` character or a `)` character.

即 **行首写 `2024.`、`1.`、`42)` 都会被解析成有序列表**（1–9 位数字都算）。（[CommonMark 0.31.2 §5.2](https://spec.commonmark.org/0.31.2/)）

对策（按优先级）：

1. **改写句式**，让该行不以数字+句点开头（最稳）。
2. 转义：`2024\.` —— 反斜杠可以转义任何 **ASCII 标点字符**（CommonMark §2.4 Backslash escapes）。
3. 把该行并入上一段，或前后加空行使其单独成段（注意：单独成段仍可能被解析为列表，必须配合 1 或 2）。

同理需转义/规避的行首字符：`#`（标题）、`-`/`+`/`*`（无序列表）、`>`（引用）、`|`（表格）、`~~~`/```` ``` ````（代码块）、`=`（Setext 标题）。**中文全角标点（。，、；：？！《》——……）不受 Markdown 语法影响，无需转义。**

### 6.4 首行缩进

- Markdown **没有**首行缩进语法。
- `　　`（两个 U+3000 全角空格）：能显示，但污染源文本、会被搜索/复制带出、各渲染器宽度不一致。**禁止在源文件里用它缩进。**
- `&emsp;` 等 HTML 实体：渲染成空格，同样污染源文本，GitHub 表格/列表中行为不稳定。**禁止。**
- **正确做法**：渲染层 CSS `text-indent: 2em`：

  ```css
  article p { text-indent: 2em; margin: 0 0 0.8em; line-height: 1.8; text-align: justify; }
  article p:first-of-type, article blockquote p, article li p { text-indent: 0; }
  ```

### 6.5 连续对话分段

每条对白独立成段、段间空一行；不要用 `<br>` 串多轮对话，不要用列表项承载对白（列表会改变缩进与行距语义）。

### 6.6 渲染层 CSS 建议（HTML 单页）

```css
:lang(zh) {
  line-break: strict;           /* 行首禁则：破折号、省略号不出现在行首 */
  text-spacing-trim: space-all; /* CJK 标点挤压（实验性） */
  text-autospace: normal;       /* CJK 与西文之间自动留白 */
  word-break: normal;
}
```

浏览器支持现状：`line-break` **Baseline Widely available**（2020 年 7 月起，[MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/line-break)）；`text-autospace` **Baseline 2025 newly available**（2025 年 11 月起，旧设备可能不支持，[MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/text-autospace)）；`text-spacing-trim` **非 Baseline、实验性**（[MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/text-spacing-trim)）。

→ 结论：**禁则用 `line-break`；中西文间距不要依赖 `text-autospace`**（源文本已手工统一加空格）；标点挤压作为增强项，缺失时不能影响可读性。

### 6.7 自动化校对

把下列检查写成脚本在 CI 里跑（`translations/zh/**/*.md`）：

1. 中文语境中出现半角 `,.!?;:` 且左右均为汉字 → 报错。
2. 出现 `「」『』`、`...`、`。。。`、`•`、`・`、`‧` → 报错。
3. 汉字与拉丁字母/数字之间缺少空格，或出现两个以上连续空格 → 报错（代码块、链接、URL、文件名内跳过）。
4. 行首匹配 `^\s*\d{1,9}[.)]\s`，或未转义的 `# - + * >` → 报错（会被解析成列表/标题/引用）。
5. 出现 `<span`、`style=`、`<font` → 报错；专名必须能在 `glossary.md` 命中。
