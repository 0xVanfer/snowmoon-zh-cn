# Snowmoon 中译 · 文体与格式规范

本文件是译制流水线的规范事实源；调研依据见 [research/](research/) 下的三份调研文档。

## 1. 交付形态

| 产物 | 路径 | 说明 |
| --- | --- | --- |
| 逐章译文片段 | `translations/zh/chapter-NN.zh.json` | 只含文字，不含结构（结构在 `sources/work/chapters/`） |
| 逐章 Markdown | `book/chapters/chapter-NN.md` | 由脚本组装，供单章阅读 |
| 全书 Markdown | `book/snowmoon-zh.md` | 由脚本组装，含目录与版权声明 |
| 中文插图 | `book/images/chapter-NN-fig-MM.svg` |视觉模型重绘，见 [pipeline.md](pipeline.md) |
| 单页 HTML | `book/snowmoon-zh.html` | 同一结构 + CSS 渲染，中文排版规则在此落地 |

原则：**结构与文字分离**。译文只改文字，标签、样式、表格布局、颜色全部由抽取脚本保留。

## 2. 受限 mini-markup（译文里唯一允许的标记）

| 写法 | 含义 | 处理 |
| --- | --- | --- |
| `<c st="oklch(0.7 0.15 93.33)">…</c>` | 彩色对话／强调（`st` 原样保留） | 译成 `<span style>`，颜色用于区分说话人 |
| `<f>…</f>` | 泽国语罗马字（虚构语言） | 不翻译，原样保留，用等宽／装饰字体渲染 |
| `<b> <i> <e>` | 加粗、斜体、着重（em） | 转 Markdown `**` / `*` |
| `<sup> <sub>` | 上下标（指数、序数） | 保留内联 HTML |
| `<code>` | 行内代码／界面字面量 | 转反引号 |
| `<a href="…">…</a>` | 链接 | 转 Markdown 链接 |
| `<br/>` | 段内强制换行 | 保留为 `<br>` |
| `<u> <small> <mark>` | 极少使用 | 保留 |

除此之外的尖括号一律视为错误。译文里**不允许**出现 `{{S:…}}`、`<div>`、`<span style>`（`<c>` 会由脚本转换）。

## 3. 标点、空格与数字（依据 GB/T 15834—2011、GB/T 15835—2011、CY/T 154—2017、W3C clreq）

- 一律使用全角标点：`，。！？；：、`；引号用 `“ ”`（内层 `‘ ’`），书名号 `《》`，间隔号 `·`（U+00B7）。
- 省略号用 `……`（两个 U+2026，共六点，不用 `...`）；破折号用 `——`（不用 `-` 或 `—`）。
- 括号：正文用全角 `（）`；**界面面板内**的方括号/圆括号保持半角 `[ ]`、`( )`。
- **中西文之间统一加一个半角空格**（CY/T 154—2017 §8.1 允许，本项目取「统一加」这一派）：`第 3 档`、`色号 92`、`AI 摘要`、`巴德拉街 1103 号`。
  - 例外：单个拉丁字母与汉字紧邻不加空格（`T恤`、`Y字形`、`X光`）；中文标点与西文之间不加空格；数字与 `%` `℃` `°` 之间不加空格（`31%`、`25℃`）。
  - 规范化脚本 `pipeline/normalize_zh.py` 会统一这件事，写作者不必纠结，但不要故意写成全角空格。
- 英文专名首现夹注原文时写作：`二次方资助（Quadratic Funding）`，全篇最多对核心术语这样做，不重复夹注。
- 数字：年份、日期、数量、序数、度量、百分比、分数值用阿拉伯数字（`3724年雪月3日`、`5,250`、`约 2 公里`、`掉 3 分`、`92 分`、`20%`）；成语、概数、固定说法与「两」的自然搭配用汉字（`一半`、`三天`、`一两个月`、`两个孩子`）。区间写作 `15%～30%`（不省略前一个 `%`）或 `第 4、5 档`（不用连接号与破折号混淆）。
- 地址写作 `巴德拉街 1103 号`、`清丘大道 980 号`。
- 度量衡换算为公制：`half-kilometer` → `半公里`，`five decimeters` → `五分米`，英里/英尺/磅 → 公里/米/公斤；保留原文数值精度，不做四舍五入。
- 货币 `zipcoins` → `齐普币`；泽国时间单位 `tick` → `嘀嗒`、`milli-tick` → `毫嘀嗒`、`longhour` → `长时`；界面数值（`44029`、`TEI 70000`、`0x18f4...60c5`）原样保留。
- 原文全大写（喊唱、标语）在中文里无法用字形表达，按普通句译出即可，需要强调时用 `<b>`；不得自造全角大写或加引号模拟。

## 4. 对话与语气

- 对话用 `“……”`；提示语在句末用 `，` 收尾：`“我赢了！”男孩喊道。`
- 原文用 `<c>` 着色区分说话人时，译文保留颜色，**不要**额外加「某某说」以免重复。
- 口头语按中文落地：`Yep` → `嗯`／`对`，`Yep, probably…` → `对，大概……`；`Wow` → `哇`；`Huh?` → `嗯？`；`Okay` → `好`／`行`。
- 不译出英语的礼貌冗余（`please`／`thank you` 视语境可省）；不添加原文没有的语气词。
- 泽国语（`<f>` 内容）保留罗马字；紧随其后的英文释义句照常译成中文（`“地下安全之所。”`），形成原文同样的「外文招牌 + 中文解释」效果。

## 5. 专名与术语

- 唯一事实源：[`pipeline/glossary.json`](../pipeline/glossary.json)；文档版：[glossary.md](glossary.md)。
- 政策：西方（维里迪亚／北极／联合城邦）专名音译；泽国（汉字文化圈设定）专名用汉字音译，读起来像中文姓名；语义透明的英文复合词意译。
- 术语表未收录的专名，按上述政策自定并写入 `new_terms`，由主进程合并进术语表后再统一复核。
- 月份名见术语表 `months`：雪月／雨月／风月／花期／草期／获月／火月／果月／葡期／雾期／霜期；日期格式 `3724年雪月3日`。

## 6. 排版与换行（写进 Markdown 与 CSS 的规则）

- **段落**：一个原始 `<p>` 对应一个 Markdown 段落，段间空行；不使用首行缩进两个全角空格，缩进由 CSS `text-indent: 2em` 提供（保证复制粘贴与纯文本阅读都不脏）。
- **对话**：一句对话独立成段（与原文 `<p>` 粒度一致），不合并、不拆段。
- **换行**：译文段落内部不硬换行（不按显示宽度断行）；段内需要强制换行处保留 `<br>`；中西文之间不加空格（属 GB/T 15834 允许且国内出版主流），但英文单词、URL、代码串不得被拆断（CSS `word-break: keep-all` + `overflow-wrap: anywhere`）。
- **避头尾**：CSS `line-break: strict`；行首禁止 `，。！？；：、）』”》`，行尾禁止 `（『“‘《`；需要时用 `hanging-punctuation: allow-end`。
- **标点挤压**：不手工塞空格来「对齐」，交给渲染器。
- **插图**：独占一行，居中，宽度自适应（`max-width: 100%`），图下不加图注除非原文有；插图文件为 SVG，通过 `<img>` 引用以隔离各图内部 id 与样式。
- **设备面板**（原文 `device-view`，模拟手表／终端界面）：以原始 HTML 块保留（表格、按钮、滑块、等宽字体），在 CSS 中统一为深色面板样式；小屏允许横向滚动。
- **分隔**：章内 `hr` → `---`；场景分隔（`scene-break`）渲染为带时间／地点的小标题行。
