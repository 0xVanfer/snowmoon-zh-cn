# 16 纠删码（Erasure Coding）

> 一句话定义：**纠删码**是把一份数据拆成 n 块、并保证「只要还剩下 k 块就能把原始数据完整拼回来」的冗余编码方案；它的代价是存储（或下载）量变成原来的 n/k 倍。

---

## 1. 它是什么

你把一份文件切碎、加点冗余、分头存到不同的地方。只要丢了不超过 n − k 块，剩下的就够你**原样**拼回来。

用参数说话：一个 **k-of-n 纠删码**（更准确说是 (n, k) MDS 纠删码）把 k 块原始数据变成 n 块编码数据，

$$\text{冗余开销} = \frac{n}{k}, \qquad \text{最小距离} \; d = n - k + 1$$

第 19 章里的「六分之五的纠删码」就是一个 5-of-6 码：n = 6，k = 5，任何 5 块都能恢复，存储量是原来的 6/5 = 1.2 倍。

## 2. 小说里它在干什么

《雪月》里有一场非法的大规模外发数据——泽和德鲁因在红郡被吞并期间要往外送出一个巨大的数据集。泽拿到的不是压缩包，而是一串文件链接：

> 「总共超过60 GB。看来我得下载其中80%。」
> （第19章，chapter-19.md:139）

**注意这里的"80%"。** 这不是压缩率，这是"我允许自己丢掉一部分"。他心里清楚：只要拿够块数，缺的那几块是可以算出来的。

具体参数是：

> 「重组算法是六分之五的纠删码，5块，每块10.7 GB。」
> （第19章，chapter-19.md:293）

也就是 n = 6、k = 5、每块 10.7 GB。后面紧跟的还有第二层：**每一块内部又套了一层语言模型隐写编码**，把密文伪装成看起来合理的文本（见 [11 语言模型隐写编码](11-lm-steganographic-encoding.md)）。所以真实的层次是：

```
真实消息（很小）
   ↓ 隐写编码（4 位密文藏 1 位明文）
载荷
   ↓ 纠删码（5-of-6）
6 块大文件，伪装成电影 / 健康数据 / AI 生成视频
```

这是本系列里非常典型的一招：**纠删码负责"容错"，隐写负责"掩护"，两者叠加。**

**另一处用在音频信道上**。第 22 章里，北极人用无人机投放到敌方的设备上偷听通话。敌方只能做一件事：往通话里塞一段"听起来像随机噪声"的背景音，里面藏数据：

> 「里面其实是被纠删码包裹的加密数据，抗噪能力很强」
> （第22章，chapter-22.md:273）

为什么这里必须是**纠删码**而不是纠错码？因为无线电干扰导致的是**整段没收到**（一片静默、一段呼啦声），不是"某个采样点偏了 1 赫兹"。这正是纠删码的主场——见第 3 节。

### 关于书里数字的一处诚实说明

按第 19 章的原文数字直接算：6 块 × 10.7 GB = **64.2 GB**（与 19:139 的"总共超过60 GB"吻合），取 5 块 = **53.5 GB**，占比 5/6 ≈ **83%**（与"下载其中80%"吻合）。在标准的 5-of-6 定义下，原始数据就是 5 块那么多 = 53.5 GB，冗余 1 块 = 10.7 GB，开销 n/k − 1 = **20%**。

但同一段里 19:291 还有一句「开销正好是6倍」，并且把"重建后多大"答成 10.7 GB——这跟 5/6 码 1.2 倍的开销对不上。仓库里没有英文原版可供核对，**书中未进一步说明**。上文的推算按「每块 10.7 GB、共 6 块」这一条原文来算，若你采用另一种读法（把 53.5 GB 当作全部 6 块总量），原始数据约 44.6 GB、冗余同样约 20%——两种读法给出的 20% 开销一致，只是绝对值不同。

## 3. 直觉：一个生活化的比喻

**纠错码**像一份带少量错别字但能读懂的作文：允许你抄错几个字，但要求**能看出错在哪里并改回来**。因为错得少，冗余也就少——你不需要为了容错而多写一整页。

**纠删码**像拼图 + 备件：你明确知道你会弄丢几块（有人在偷你、服务器会下线、信号会被干扰），所以干脆多发几块备件，**整块丢了也无所谓**，剩下的碎片里有足够的冗余能推断出丢失的那块。

一句话对比：

| | 纠错码（error-correcting） | 纠删码（erasure） |
| --- | --- | --- |
| 你知道坏在哪吗 | **不知道** | **知道**（丢了就是丢了） |
| 处理什么 | 比特被翻转 / 数值被轻微污染 | 整块 / 整段完全没有 |
| 需要的冗余 | 少量 | 较多 |
| 现实例子 | 手机信号纠错、硬盘 ECC、光盘 | CDN 分片下载、卫星存储、CDN 容灾 |

**这个"知道坏在哪"是决定性的。** 设想一条信道，每传 1000 个比特，坏掉 1 个：

- 纠错码：需要冗余来覆盖这些**随机散落**的坏比特，冗余比例取决于最坏情况下坏多少个。
- 纠删码：直接告诉解码器"第 37 块和第 512 块丢了"，冗余可以少很多，因为不用去"猜"哪里错了。

信息论里这个差距是可以量化的：纠删码的最优冗余是精确的 n/k；纠错码要在"能纠正多少个错误"和"要多少冗余"之间做曲线权衡。**代价是纠删码完全不能处理"块在但内容错了"的情况。** 实践中两者常串联：先用纠删码抗丢失，再用纠错码处理残余误码。

第 22 章那段的措辞是「抗噪能力很强」——严格说，那是因为信道丢的是整段（擦除），如果真的混入随机比特翻转，还得再叠一层纠错码。

## 4. 原理

### 4.1 最小的距离界：为什么 d = n − k + 1

纠删码的判定标准是**最小距离 d**：任意两组编码数据之间，至少有 d 个位置不同。

对 (n, k) MDS 码有 d = n − k + 1。以 (3, 2) 为例：d = 3 − 2 + 1 = 2，意思是**任何两块都绝不会一模一样**。这正是"任意 2 块能恢复第 3 块"的原因——如果有两块相同，你连它们是同一份数据还是两份恰好相同的数据都分不清。

这个 d − 1 = n − k 的关系就是**Singleton 界**，它告诉你：(n, k) 纠删码在"任何 k 块可恢复"的前提下，冗余不可能少于 n − k 块。RS 码是能达到这个界的，所以被叫作 MDS 码。

顺带一提，同一个距离参数换个读法就是纠错能力：d 元的码可以纠正 ⌊(d−1)/2⌋ 个**错误**，或纠正 d−1 个**擦除**。2 > 1，所以纠删码在擦除上效率高一倍——这又是同一个道理。

### 4.2 Reed–Solomon 码：把"拼回去"变成"求一条线"

RS 码的想法非常几何：**把 k 个数据块当作 k 个点，编码 n 块就是去一条曲线上再取 n 个点。**

最简单的 (3, 2) RS 码就是一条**直线**。设两段数据是 m₀、m₁（各当作一个"数"）。让直线 P(x) = m₀ + m₁·x 通过点 (0, m₀) 和 (1, m₁)，然后在 x = 0、1、2 三处取值：

| 编码块 | 位置 | 值 |
| --- | --- | --- |
| c₀ | x = 0 | m₀ + m₁·0 = **m₀** |
| c₁ | x = 1 | m₀ + m₁·1 = **m₀ + m₁** |
| c₂ | x = 2 | m₀ + m₁·2 = **m₀ + 2·m₁** |

现在丢一块试试（全部在 GF(256) 也就是 8 位二进制的算术里做，加减都是异或）：

**丢 c₂**（已知 m₀ 和 m₀+m₁）：`m₁ = c₁ − c₀`，`m₀ = c₀`。✓
**丢 c₁**（已知 c₀、c₂）：`m₁ = (c₂ − c₀) / 2`，`m₀ = c₀`。✓
**丢 c₀**（已知 c₁、c₂）：`m₁ = c₂ − c₁`，`m₀ = c₁ − m₁`。✓

**任何两块都够**，因为**两个点唯一确定一条直线**。这就是 RS 码的全部直觉。

一般情况：k 块数据 → 找出通过这 k 个点的 k−1 次多项式 → 在 n 个不同位置求值。任意 k 个点唯一确定一个 k−1 次多项式（这就是拉格朗日插值定理），所以任意 k 块都能还原。

**为什么是范德蒙德矩阵？** 编码就是构造一个 n × k 的矩阵（取不同横坐标处求值，所以每行是 1, x, x², …, x^{k−1}，即范德蒙德矩阵）乘上数据向量：

$$c = G \cdot m, \quad G_{i,j} = x_i^{\,j}$$

你手上有哪 k 块，就取 G 中对应的 k 行，得到一个 **k × k 方阵**。只要它可逆（范德蒙德矩阵在 x 互不相同时必然可逆），解一个线性方程组 $G_k m = c_k$ 就能拿回 m。这就是编码和解码的**全部**内容——没有魔法，就是解方程组。

**⚠️ 一个必须交代的细节**：上面所有加减乘除都在**有限域**里做，不是普通整数。真实 RS 码用的是 GF(2⁸)（256 个元素的域），域里的"除法"是乘以逆元（逆元由扩展欧几里得或查表得到），所以不存在"整数除不尽"的问题。如果在普通整数上做，第 4 步的 `/2` 就未必有解了。

### 4.3 喷泉码：你不需要事先知道要拿几块

RS 码有个前提：**你事先知道 n 是多少**，也知道去哪些地方拿。但如果场景是"文件散布在无数个做种者手里，你不知道总共有多少份"（BitTorrent 式的分发场景），RS 就不合用了。

**喷泉码（LT 码 / Raptor 码）**放松了这个要求：编码端**没有停止时间**，可以无限生成编码块，每一块都带一个随机种子，**任何一小批（约 1.05k 到 1.2k）都能独立恢复原始数据**。

工作方式是"剥洋葱"（peeling）：

1. 拿一批块，检查有没有哪块的"度数"（它依赖的下级块数）已经全部被满足；
2. 如果有，就用它减出它的下级块，把这些下级块的度数减 1；
3. 重复 3，直到恢复出全部 k 个原始块。

这正好匹配第 19 章的场景：泽有 60 GB 的链接清单，知道自己只需要 80%，**边下边解**，不需要先规划"这 6 块我要哪 5 块"。Raptor 码在前一步加了一层"预编码"（预编码 + 喷泉），单次解码成功率更高，是实际标准里用的那一个（RFC 6330 定义了它）。

**取舍**：RS 解码快、率高，但必须知道 n；喷泉码能应对"不知道 n"的场景，天然支持随机访问（缺第 3 块不影响你先去解别的），但通常要下载 1.05k~1.2k 块，冗余更高，解码也更慢。

### 4.4 编码放在哪一层：为什么通常"先加密、后纠删码"

这一条很反直觉，是真实世界反复吃过亏的地方。

**纠删码的本质是线性的。** 用 4.1 的式子看：c = G·m。编码是**对数据的线性变换**。而**加密变换对明文结构的泄漏**这件事，在线性密码里是致命的：Shamir 在分析 CTR 模式时就指出过，**CTR 模式的加密输出对明文 XOR 差分是线性的**（密文的异或 = 明文异或），所以流密码叠加（xor 出来的）数据一旦被"纠删码化"再经过攻击者的选择明文，结构会层层暴露。

**所以正确顺序是：先加密，再纠删码。**

加密 → 密文已经对明文结构免疫 → 再对密文做线性编码 → 得到的码字在结构上与明文无关。

反过来的顺序（先纠删码、后加密）也不是绝对错误（很多 P2P 存储系统为了能对单块做随机访问，反而故意先编码后加密），但代价是：单块无法独立解密、必须凑齐 k 块才能读，且对**选择明文攻击**的抵抗力需要额外论证。

**第 19 章的顺序恰好是安全的**：先对载荷做隐写编码（隐写本身是加密的一种形式），再对**隐写后的载荷**做纠删码。换句话说，那句"每一块又是一层隐写编码"里的"又"字，说明纠删码是在**已经不可读的载荷**外面套的。**这里顺序是对的。**

## 5. 关键参数与真实世界的取值

| 参数 | 含义 | 现实中的典型取值 |
| --- | --- | --- |
| 冗余开销 n/k | 存储放大倍数 | 冷存储 1.3~1.5；高耐久 1.8~2.0（HDD 阵列）；跨机房容灾 2.0 |
| 纠删能力 | 能容忍多少块丢失 | n − k；HDD 阵列常见 8+3、12+4（n/k = 1.375、1.33） |
| 码长 n | 一次编码的总块数 | 从 5 到数千。n 很大时单块变小，块管理开销上升 |
| 符号大小 | 每块的字节数 | 通常 1 KB ~ 1 MiB。太小的块让元数据和请求开销爆炸 |
| 分块策略 | 跨多少机架 / 多少机柜 | Ceph 的 EC 池默认按机架打散，保证丢的是机架而不是单盘 |
| 恢复时并发 | 恢复时读几块 | 有限并发（默认 8~16），避免恢复拖垮正常业务 |
| 喷泉码冗余 | 实际下载量 / 原始量 | 1.05 ~ 1.2（RFC 6330 的 Raptor 建议 1.01~1.05 的期望额外比例） |

**第 19 章的 6/5 属于"轻量"档。** 1.2 倍开销意味着能扛住 1/6（约 17%）的数据丢失。真实世界的存储阵列通常更保守：HDD 便宜但不可靠，常用 8+3（n/k = 1.375，可容忍 3 块）；SSD 贵但可靠，2+1 甚至 1.5 折半（n/k = 1.5~1.67）都有人用。**冗余比例是"抗损坏能力"直接换来的，不是免费的。**

## 6. 容易误解的地方

**误解一：「纠删码是压缩技术。」** ❌
纠删码不减小体积，它**增大**体积。RS 6/5 的意思是"存储 53.5 GB 只为放 44.6 GB（另一种读法）或放 53.5 GB 原始数据只多占 10.7 GB"，总之是放大。**唯一"省"下来的东西是可靠性本身。**

**误解二：「下载 80% 就能还原 100%，那 20% 去哪了？」** ❌
这是最容易懵的一处。第 19 章里那 6 块是**冗余块**。5-of-6 意味着"6 块里任何 5 块够用"，也就是 5/6 ≈ 83%，剩 1/6 是**纯粹为了容错而存在的冗余**，本身不携带新的原始信息。反过来说：如果你只下了 3 块，无论压缩算法多好都拼不回来。

**误解三：「纠删码也能修'内容错了'。」** ❌
这是纠删码最本质的短板。纠删码的前提是"**丢了**"，不是"**坏了**"。如果某块在，但里面的数据被磁化、位翻转、被人篡改，纠删码**不但发现不了，还会把这个错误当作真实数据参与计算**，导致还原出一份彻底错误的数据。这也是为什么真实系统里 RS 之后一定还要叠一层纠错码 + 校验和（如 CRC）。**纠删码保证"不丢"，不保证"不坏"。**

**误解四：「隐写在纠删码外面就够了，加密是多余的。」** ❌
这两层解决的是完全不同的威胁：
- 纠删码解决的是"**完整性/可用性**"——能不能凑齐数据；
- 隐写解决的是"**存在性**"——让旁观者看不出这里有东西；
- 加密解决的是"**内容机密性**"——**一旦有人把隐藏的比特挖出来，没有加密他就能读懂**。

第 19 章第 293 行恰好点破了这一层：德鲁因（伪造出来的说书人）主动指出了，电影的选择本身就是密钥——也就是说**隐写层的安全性完全依赖于"选哪几部电影"这个秘密**。一旦这个秘密泄露、或者对方有耐心逐位提取，数据就裸奔了。密码学的通用原则是：**真正的机密性必须来自密码学，而不是来自"藏得够深"。**

**误解五：「RS 是最省的选择。」** ⚠️
RS 是 MDS 码，冗余达到了 Singleton 界，**在"任意 k 块可恢复"这个指标上无法更省**。但它有固定开销：编码本身要乘矩阵，块要凑齐才能解，而且**必须知道 n**。喷泉码、LDPC 码在某些场景更划算。**指标（能不能任意 k 块恢复）是前提，冗余比例是这个前提下的最优解，不是"最省"。**

**误解六：「第 22 章说'抗噪能力很强'，说明纠删码能抗噪。」** ⚠️
原文说的是「抗噪能力很强」，但这里的"噪"是通信意义上的**信号丢失**。纠删码抗的是"整段收不到"，不是"个别采样点有偏差"。真要处理连续信号里的随机失真，还是要靠卷积码、LDPC 这类**纠错码**。这里应该理解为译者/原文的宽泛表述。

## 7. 自己动手试试

**手写一个 5-of-2 的 RS 码，验证任意丢一块都能恢复。**

下面的代码在一个真实的有限域 GF(2⁸) 上运算（原多项式 x⁸+x⁴+x³+x²+1），不是整数运算：

```python
# GF(2^8) 算术表：加法 = 异或，乘除 = 查表
EXP = [0]*512; LOG = [0]*256
x = 1
for i in range(255):
    EXP[i] = x; LOG[x] = i
    x <<= 1
    if x & 0x100: x ^= 0x11D          # 溢出就减去原多项式
for i in range(255, 512): EXP[i] = EXP[i-255]

def mul(a, b): return 0 if a==0 or b==0 else EXP[LOG[a]+LOG[b]]
def div(a, b):
    assert b != 0
    return 0 if a==0 else EXP[(LOG[a]-LOG[b]) % 255]

# 编码：k=2 -> n=3，直线 P(x) = m0 + m1*x 在 x = 0,1,2 处取值
def encode(m0, m1):
    return [m0, m0 ^ m1, m0 ^ mul(2, m1)]

# 解码：拉格朗日插值，由任意两个已知点算出缺失点
def lagrange(known, X):
    total = 0
    for xi, yi in known:
        num = den = 1
        for xj, _ in known:
            if xj != xi:
                num = mul(num, X ^ xj)
                den = mul(den, xi ^ xj)
        total ^= mul(yi, div(num, den))
    return total

m0, m1 = 0b10110110, 0b01101101
blocks = encode(m0, m1)
print("原始 2 块 :", format(m0,'08b'), format(m1,'08b'))
print("编码 3 块 :", [format(b,'08b') for b in blocks])

for miss in range(3):
    known = [(i, blocks[i]) for i in range(3) if i != miss]
    got = lagrange(known, miss)
    print(f"  丢掉第 {miss} 块 -> 恢复 {format(got,'08b')} "
          f"{'OK' if got == blocks[miss] else 'FAIL'}")
```

实际输出（三种丢失情形全部恢复成功）：

```
原始 2 块 : 10110110 01101101
编码 3 块 : ['10110110', '11011011', '01101100']
  丢掉第 0 块 -> 恢复 10110110 OK
  丢掉第 1 块 -> 恢复 11011011 OK
  丢掉第 2 块 -> 恢复 01101100 OK
```

**然后把 `mul(2, m1)` 换成普通整数运算 `2 * m1`，再跑一次。** 你会发现"丢第 0 块"这种情况开始失败——因为 2 在普通整数里不是每个数都有逆元。这直观地解释了**为什么必须在有限域上运算**。

**接着算一遍第 19 章的账。** 6 块 × 10.7 GB = 64.2 GB；取 5 块 = 53.5 GB；53.5 / 64.2 = 83.3%；冗余 = 1 块 = 10.7 GB，占原始的 20%。和原文「总共超过60 GB」「下载其中80%」对一对，你就明白"80%"是什么意思了。

**再试试喷泉码的思路。** 找一份大文件，用 `aria2c -x 16 -s 16` 之类支持多连接分片的工具下载，然后在下载过程中随机杀掉 1~2 个连接，看能不能续传完成——那背后跑的就是"边下边解"的分片逻辑。

## 8. 自测

**第 1 题**　纠错码和纠删码最根本的差别是什么？请各举一个"只有它管用"的场景。

> **答案**　根本差别在于**接收方是否知道哪里出了问题**。纠错码用于"不知道哪里错了"的情况（比特被随机翻转），它靠冗余去**定位**错误位置，因此冗余必须覆盖最坏情况；纠删码用于"明确知道哪几块丢了"的情况（整块消失），它不必浪费冗余去猜，因此同样保证下冗余可以少得多。量级上，d 元的码可以纠正 ⌊(d−1)/2⌋ 个错误、或纠正 d−1 个擦除——擦除的纠正能力是错误的两倍。只有纠删码管用的场景：卫星/深空通信（整段信号丢失）、CDN 分片下载（部分节点下线）、跨机房存储（整机架故障）。只有纠错码管用的场景：手机信号纠错、光盘/硬盘 ECC、无线传输中的随机误码——因为这些场景下"哪里错了"是未知的。

**第 2 题**　第 19 章说泽要下载 80% 的链接就能还原全部数据。结合"5块、每块10.7 GB、6块总量超过60 GB"，请算清楚：原始数据有多大？冗余有多大？那个"20% 省下来的"到底是什么？

> **答案**　6 块 × 10.7 GB = 64.2 GB 总量，取 5 块 = 53.5 GB，占 5/6 ≈ 83%，与原文"下载其中80%"吻合。在标准 5-of-6 定义下，原始数据 = 5 块 = 53.5 GB，冗余 = 1 块 = 10.7 GB，冗余占原始的 10.7/53.5 = 20%（即 n/k − 1 = 1.2 − 1）。那个"省下来的 20%"**不是省下来的，是纠删码故意多放进去、专门用来顶替丢失的那一块的冗余**。删掉 1/6 的数据之所以还能还原，正是因为那 1/6 是冗余而非信息。必须强调：纠删码从不减小体积，只增大体积（1.2 倍），它"换"来的是抗丢失能力。（注：同章 291 行另有"开销正好是6倍"一语，与 5/6 码 1.2 倍的开销不符，仓库无英文原版可核，书中未进一步说明。）

**第 3 题**　为什么第 19 章把"隐写编码"套在纠删码**外面**（先隐写、后纠删码）是正确的？反过来做会有什么风险？

> **答案**　因为**纠删码是线性变换**（c = G·m，编码本质上是对数据做线性映射），而线性结构会泄漏明文的结构特征；同样，加密模式对明文 XOR 差分呈线性关系（CTR 模式是经典例子）。先做隐写／加密，明文结构就已经被"打散"成看起来随机的比特，再对这份不可读的载荷做线性编码，得到的码字就与明文结构无关。反过来（先纠删码、后加密）不是绝对错误——很多 P2P 存储系统故意先编码后加密以换取单块随机访问——但代价是单块无法独立解密、必须凑齐 k 块才能读，且对**选择明文攻击**的抵抗力需要额外论证。核心教训是：**安全性质必须作用在最外层可见的那一层**；任何"藏得够深"的方案都不构成密码学保证。
