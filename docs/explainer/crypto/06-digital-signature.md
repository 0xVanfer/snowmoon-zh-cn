# 06 数字签名与公钥基础设施（Digital Signatures and PKI）

> 数字签名是「用只有我有能力用的那把钥匙，在消息上加一个别人算不出来、但人人都能验的章」；公钥基础设施解决的是「验章要用哪把章」。

## 1. 它是什么

三样东西配套：

- **密钥对**：一把私钥（只有你有）和一把公钥（人人都能拿）。用私钥能签名，用公钥能验签。
- **签名**：一段数据，由私钥对消息计算得到。任何人用对应公钥都能验证签名是否有效。
- **公钥基础设施（PKI）**：一套规则和登记机制，回答「**这个公钥属于谁？**」「**它什么时候生效？**」「**它什么时候作废？**」

签名提供三条保证，缺一不可：

| 保证 | 意思 |
| --- | --- |
| **真实性** | 这个章是持有那把私钥的人盖的 |
| **完整性** | 消息一个字都没被改过（改了签名就验不过） |
| **不可否认性** | 盖了章的人在事后无法否认（因为只有他有私钥） |

**签名不提供第四样东西：保密性。** 这一条会在第 6 节展开，因为它是最常见的误解。

## 2. 小说里它在干什么

《雪月》里，签名承担了「**把设备身份和厂商绑定，并让全网都能查证**」这个基础设施角色。第9章把它讲得最完整：

| 第9章，chapter-09.md:171 | 「然后你拿从密码学网络上下载的公钥去验这个签名」 | 验证路径：你手上永远有最新公钥 |

签名在别处的用法：

> 「只有用有效密钥签名的票才算数。」（第15章，chapter-15.md:81）
> 「已经签好3个。还差一个。」（第16章，chapter-16.md:205）——4 把恢复密钥里凑 3 把联署

第16章那次交易还顺手展示了**签名和加密的分工**，两句相隔两行，值得并排读：

> 交易请求内容：「[钱包 0x8f62... 社交恢复模式交易请求]」（第16章，chapter-16.md:187）

**先加密内容，再对内容签名。** 缺任何一步都不行：只有签名 → 人人可见你买了什么；只有加密 → 收钱的人无法证明你授权过。

至于**访问密钥**这种老式用法（公钥当成密码用），第30章还留着：

## 3. 直觉：一个生活化的比喻

**比喻：火漆封印。**

你写一封信，折起来，用一滴火漆按上你的私章。信送到对方手上时：

- **漆还是热的、印还是那个形状** → 这封信**没被拆开换过**（完整性）；
- **这个印只有你有** → 盖这个印的**就是你**，别人伪造不出来（真实性）；
- **事后你说「这印不是我的」** → 没人信，因为印模（私章）在你那儿（不可否认性）；
- **信里写了什么** → **火漆一点都没告诉你**。它只保证「没动过」，不管「里面是什么」（**签名不保密**）。

**「只有我有能力盖」这一条是关键。** 真实火漆的强度来自「你得亲手把蜡加热、再用那枚印去压」。数字签名的强度来自同一个抽象：**私钥承担「只有你能做这个动作」的角色**。

第二层比喻，解释**为什么要搞一套公钥分发系统**：总不能每封信都让收信人打电话问你「这个印是你的吗、什么时候刻的、还作废没」。所以需要一处**大家都信的地方**，公钥在那里登记、签名在那里盖章、时间在那里留下。

**登记册的现代形态是「透明日志」**（第 4.3 节）——它不是把证书锁在一只保险柜里，而是**每一份登记都公开、追加写、任何人都能查**。

## 4. 原理

### 4.1 签名到底做了什么（Ed25519 为例）

现代签名算法（如 Ed25519）大致是这个流程，细节各不相同但骨架一致：

1. **生成密钥对**：随机取一个 32 字节的**私钥种子** $s$；公钥 $A = [s]B$，其中 $B$ 是那条曲线上公开的基点（这一步是椭圆曲线上的标量乘）。
2. **签名**：把消息哈希成 $H(M)$，再结合私钥算出签名 $\sigma = (R, S)$ 这样的两个短量。
3. **验签**：任何人有公钥 $A$，就能检查一条代数等式是否成立；成立则签名有效。

**第 3 步不需要私钥。** 这是全部设计的核心：公钥天生是公开的（术语表把 physical unclonable function 注为「芯片制造中由化学沉降自然生成的不可复制密钥」——那把连厂商自己都读不出的私钥，就是芯片的签名身份）。

第9章那段关于设备公钥的对话里，人物自己就修正了一次用词——把公钥叫成「p 乘 q」被当场纠正：「不过我现在知道了，根本不是 p 乘 q，是完全不同的东西」（chapter-09.md:167）。**这句话是作者借人物之口提示读者：ECC 的公钥不是两个大数相乘**，见 [08 椭圆曲线与后量子签名](08-elliptic-curves-and-pqc.md)。

### 4.2 签名和加密：两件不同的事

| | 加密 | 签名 |
| --- | --- | --- |
| 用哪把钥匙 | 收件人的**公钥**加密，私钥解密 | 发送者的**私钥**签名，公钥验签 |
| 解决的问题 | 内容**不被读** | 内容**不被改**、来源**可确认** |
| 需要保密密钥吗 | 需要 | 不需要 |
| 公钥需要保密吗 | **需要**（公钥就是「锁」） | **不需要**（公钥就是「验章器」） |

**注意最后一行：公钥在两套体系里的地位完全相反。** 加密里公钥可以公开（只是效率问题），但习惯上当成收件人的身份；签名里公钥**必须公开**，否则没人能验。

所以现实中的标准动作是**两个一起用**：用接收者的公钥加密（只有他读得懂），再用自己的私钥签名（证明是我发的）。第16章那笔交易正是这个组合（chapter-16.md:187、191）。

### 4.3 为什么要「公钥分发网络」，透明日志解决什么

**问题：公钥本身不能证明它属于谁。** 一份公钥文件是公开的，任何人都能生成一份。任何人都能用它验签。**「这个公钥是 A 厂商的」这件事，必须由某处背书**——这就是证书和 PKI 的存在理由。

传统的做法是**认证机构（CA）**：你提交材料，CA 验证后给你一张证书。问题是：CA 成了一个**必须被信任的中心**，而且历史上出过大事故。2011 年的 DigiNotar 事件中，一家挪威 CA 的密钥被攻破，攻击者用它签发了 Google、Skype 等公司的假证书，主流浏览器随后集体吊销了对它的信任。**这暴露了「谁给 CA 背书」这个问题的递归性。**

现代解法是**透明日志（transparency log）**，思路有两个转变：

1. **从「中心保管」变成「公开追加」**：所有登记进一个**只增不改**的公开日志。任何人都能（a）自己下载整份日志，（b）拿到某条登记时拿到**一份密码学证明**，证明「这条记录确实在日志里，且前后没有被塞进别的记录」。
2. **从「相信 CA」变成「所有人都能自己核对」**：你不需要信任日志运营者，只需要验证那个**一致性证明**——一旦运营者偷偷插入了假记录，全网任何人都能算出来。

**「可验证的公共登记」是这套东西的真正目标。** 第9章那句「再把这把公钥连同签名一起发布到密码学网络上」（chapter-09.md:167）就是它：你的手表查证无人机时，用的是从网络下载的公钥（chapter-09.md:171），**而不是某台服务器递给你的一个「已验证」标记**。

**密钥透明（key transparency）**是这一思路的加强版：不只登记证书，还登记**某个身份名下所有公钥的完整历史**。这样一来，「某个身份突然多了一把新钥匙」这件事**必然被看见**——攻击者偷了私钥并注册新公钥，登记会留下痕迹。

### 4.4 时间戳：为什么它能区分「失窃前后」

这是第9章那段里最精彩、也最容易被跳过的一招（chapter-09.md:177）：

> 「万一厂商的密钥被偷了，你还能分辨签名是在失窃之前还是之后做的。」

**问题**：厂商密钥被盗，攻击者用它签了一堆假公钥。事后怎么判断**哪一份签名是泄露前合法签的、哪一份是泄露后伪造的**？

**没有时间戳时：不可能。** 两批签名在数学上完全一样，唯一区别是**什么时候做的**——而签名本身不记录时间。

**加上时间戳后：可以。** 给每份签名配一个**由独立可信的时间戳机构（TSA）盖的时间戳**，签名内容里就包含了「这份签名存在于某个时刻」的可验证证据。于是判断规则变成：

- 时间戳 **早于** 密钥失窃时刻的签名 → 泄露前完成，**按原件处理**；
- 时间戳 **晚于** 失窃时刻的签名 → 有可能是攻击者签的，**按可疑处理**。

现实里对应的标准是 **RFC 3161（Time-Stamp Protocol）**。这类签名称为**带时间戳的签名**，常用于代码签名和长期存证。

**这一招的价值在于它不试图「证明签名是好的」，而是「把签名放到一条可信的时间线上」。** 前者依赖密码学，后者依赖**一个带外的时间见证**——所以它对「密钥被盗」这种**密码学完全无能为力**的攻击特别有效。

## 6. 容易误解的地方

**误解一：签名 = 加密 = 保密。** **这是本文档里最需要先拆掉的一个误解**，而且第16章已经用两行并排把两者区分开了（chapter-16.md:191 与 chapter-16.md:205）。

- 签名**不保密**。你签一份东西，等于把「是我签的」和「内容一个字没改」这两件事**公开绑定**给所有看到签名的人。
- 保密靠**加密**，不靠签名。
- 现实做法是**先加密再签名**；顺序反了（先签名后加密）签名也就没意义了，因为签名本身在明文里。

第16章那笔交易恰好是反过来的正确姿势：**加密内容（防第三方读），再让 3 个联署者签名（防抵赖）**。

**误解二：公钥是秘密的。** 反了。**公钥必须公开**，否则没人能验签——这正是第9章「发布到密码学网络上」（chapter-09.md:167）的意义。反倒是私钥必须严格保密（芯片里那把连厂商都读不出的 PUF 密钥，chapter-09.md:167）。「访问密钥」那种把公钥当密码用的老做法（第30章，chapter-30.md:9）现在只适合低风险场合，因为公钥本来就是公开的。

**误解三：厂商密钥被盗 = 所有签名全废。** 在**没有时间戳**的世界里是这样；第9章明确指出了破法（chapter-09.md:177）：每份签名都带上可信时间戳，失窃时刻就成了分界线。**这能救回失窃前的签名，但救不回「那一刻之后怎么办」**——所以现实里密钥泄露的标准动作仍然是**立即轮换（rotate）**，时间戳只是让历史记录可解释。

**误解四：有了签名，签名者就是「同意了这个内容」。** 签名只证明「**用这把私钥算出了这个签名**」。它不证明签名者读过内容、理解内容、或者真同意。**「我签了」和「我同意」之间隔着整个界面设计。** 现实里的钓鱼攻击利用的正是这个空隙：你签的是一份你看不懂的授权。

**误解五：验证通过 = 对方身份没问题。** 第3章那 55 台设备里有 6 台没有认证（chapter-03.md:157），提醒的是另一件事：**没通过验证的设备同样存在，而它们是攻击面**。「验证通过」是必要条件，不是安全保证。

## 7. 自己动手试试

1. **亲手做一次「签名 ≠ 保密」的演示。** 写三行字：(1) 你的名字，(2) 一个秘密（比如你家的门牌号），(3) 一句声明。在 (2) 上画一道横线当「签名」。然后把你的纸给同学。**请他说出三行的内容。** 他能读出 (1) 和 (3)，也能确认「这一行没被改过」，但**「签了名的那一行」照样公开可读**。这就是签名不保密的直观版本。

2. **测「有效性」。** 同一张纸，请同学**只改 (1) 那一行的一个笔画**，别动签名。**签名立刻对不上**——这就是完整性。反过来，**只改签名**也对不上。这就是真实火漆封法的全部功能。

3. **手工做一个门限签名（模拟 4 选 3）。** 找 4 个人，各写一句「我批准这笔转账：编号 7」。然后挑 3 句，凑成「3-of-4 联署」。测试：① 换掉其中一句里的编号，联署还能用吗（不能——任何一句变了整体就变了）；② 只用 2 句行不行（不行——这正是第16章「还差一个」的意思，chapter-16.md:205）；③ 4 句全给，能看出是谁参与了吗（**能，这就是门限签名的代价**：参与者和数量会被公开）。

4. **体会「下载公钥」和「接受公钥」的区别。** 想象两种场景：①厂商给你发一封邮件说「这是我的公钥，请收下」；②你自己从密码学网络上下载（chapter-09.md:171）。**第 ② 种多了什么？** 多了一次独立核对：**你可以查这份公钥是不是厂商自己发布的、什么时候发布的、发布过几版**。**这就是透明日志和 key transparency 想给普通人的东西**（4.3 节）。

## 8. 自测

**第 1 题**：第9章说厂商把自己的公钥连同签名一起发布到密码学网络上（第2节 chapter-09.md:167、171）。假设你今天下载到的那份公钥签名验证通过，**这能不能证明「这架无人机是正版」**？还差哪几环？

> **答案**：**不能**。验证通过只证明三件事：①这份公钥确实被那把厂商私钥签过；②你手上的消息（公钥）没被改过；③签名确实属于这把公钥。**它完全不涉及硬件本身。** 缺的环节至少有两个：**(a) 公钥与这台具体机器的绑定**——需要芯片里那把 PUF 私钥配合「让设备对一个值签名」的动作（第9章 chapter-09.md:171 描述的正是这一步），否则同一份签名可以被复制到无数台机器上；**(b) 设备确实在跑它声称的软件**——这属于远程证明的范畴，签名不解决。签名只负责**「谁签了这把钥匙」**这一环。

**第 2 题**：厂商的签名密钥被盗，攻击者签了 50 份假公钥。chapter-09.md:177 说时间戳能让你「分辨签名是在失窃之前还是之后做的」。请说清：①签名本身为什么做不到？②时间戳是怎么做到的？③这个办法的**边界**在哪里？

> **答案**：①签名本身不记录时间——它只是私钥对消息算出的一段数学值，失窃前签的和失窃后签的**在形式和强度上完全一样**，事后无从区分。②带时间戳的签名（RFC 3161 那一类）由**独立的可信时间戳机构**盖一个含时间的凭证，签名时把「我存在于此刻」这件事变成可验证证据。有了可信时间线，失窃时刻就成了分界线。③**边界**：它只能把签名**分类**，不能告诉你泄露后的签名一定是假的——攻击者完全可以在失窃后立刻签。而**泄露之后唯一的补救是轮换密钥**。另外，如果时间戳机构和签名密钥来自同一个被攻破的来源，整条时间线一起失效。

**第 3 题**：第16章里，格拉迪亚斯要付一笔钱，两个动作各解决什么问题——「这些数据当然全程加密」（chapter-16.md:191）和「已经签好3个。还差一个」（chapter-16.md:205）？为什么两个都要？

> **答案**：**加密**解决**第三方保密**：数据字段在密码学网络上全程加密，旁观者（包括餐厅之外的节点）看不到买的是什么、寄到哪。**签名（3/4 联署）**解决**授权与不可否认**：只有恢复密钥持有者才能授权动这笔钱，而且事后不能否认「我没批过」。**两个都要，因为它们防的是不同的攻击者。** 少了加密，别人知道你买了什么；少了签名，别人可以伪造你的付款请求，而你无法证明那不是你批的。反过来，**顺序不能错**：先加密内容、再对内容签名，签名的意义才完整。
