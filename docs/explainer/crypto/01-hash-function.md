# 01 哈希函数（Hash Function）

> 把任意长度的数据，压缩成一个定长的、独一无二的「指纹」，并且**压到找不出碰撞为止**。

## 1. 它是什么

哈希函数是一个函数：进去任意长度的数据，出来一个固定长度的数字。

```
「雪月」这本书一共三十二章
        │
        ▼
   ┌─────────┐
   │ 哈希函数 │   无论输入多长（0 字节还是 100 GB），
   └────┬────┘   输出永远一样长
        ▼
   3a7f9c2e1b...（256 位）
```

它必须满足四件事：

| 性质 | 含义 | 违反会怎样 |
| --- | --- | --- |
| **确定性** | 同样的输入永远得到同样的输出 | 没法用来核验 |
| **单向性** | 给你指纹，反推原文在计算上不可行 | 密码泄露了 |
| **定长输出** | 输入再长，输出长度固定 | 没法当固定大小的地址用 |
| **抗碰撞** | 找两份不同内容却撞出同一指纹，数据上不可行 | 「防篡改」全部失效 |

书里对这个定义说得非常准。泽在读密码学教材，第 12 章：

> 「书上说，哈希算法的作用，是一大块信息生成一个缩小后的指纹，而这个指纹仍然能唯一标识原来的信息。它的目标是：要想找出两段哈希相同、内容不同的数据，在计算上难到不可行。」
> ——第12章，chapter-12.md:107

注意作者用词的精确：「**仍然能**唯一标识」加上「**在计算上难到**不可行」。哈希**不是**数学上的一一映射，它只是**实际中撞不上**。这个区别是本文最重要的一个点。

## 2. 小说里它在干什么

哈希在这个世界里几乎无处不在，承担四个互相独立的职责：

**（一）身份与所有权的公开凭证。** 厂商造完芯片，生成一枚哈希发布到密码学网络；任何人拿这枚哈希就能查证"这台设备确实出自那家厂商的某一批"（chapter-03.md:157：「如今几乎每台设备都带零知识证明，验明它由某家厂商的某个批次生产」）。

**（二）防重放的作废符。** 格拉迪亚斯拿信誉借钱的流程里，作废符就是一段伪随机哈希，公开可见但**不可关联回是哪条评语生成的**（chapter-06.md:269）。详见 [05 作废符与零知识抵押](05-nullifier-and-zk-collateral.md)。

**（三）可信日志的锚。** 摄像头每次"吐数据"（判定可疑并外传）就往密码学网络发一个哈希，于是**触发次数变成公开可查的量**——公众能验证"这批摄像头一共报警过 37 次"，厂商没法偷偷上报（chapter-05.md:157）。这是现实中的**透明日志**（transparency log）思路。

**（四）密码学证明的基石。** 银聊把"可读消息集合"的哈希发布到网络上，改代码就得发新哈希，并且**强制等待 20 天**（chapter-27.md:47）。整个约束是"你不能偷偷改规矩"。

## 3. 直觉：指纹，但指纹会撞

现实中的指纹也一样：两个人可能撞指纹。所以指纹不是"数学上唯一"，只是"实际上不撞"。

更贴切的类比是**图书馆的书脊标签**。一本书被压缩成一行数字和字母，贴在书脊上。你能一眼认出这是哪本书，但反过来——给你一串字符——你没法把整本书还原出来。而且书脊空间有限（256 位），所以理论上有极小概率两本书贴出同一个标签。

这里有一个**必须想清楚的悖论**：

> 100 GB 的书，压成 256 位（一个能装下 10⁷⁷ 个不同标签的空间）。这是**必然**丢信息的——空间变小了。
>
> 那么，为什么碰撞还"难到不可行"？

因为「难到不可行」**不是**指"在信息论上不可能"。它指的是：**除非你挨个试遍 2²⁵⁶ 种可能的输入，否则没有任何捷径能找到一个碰撞**。这是一个关于**计算量**的断言，不是关于**信息量**的断言。

这就是全书最值得学的一个区分：

- **鸽笼原理**（信息论）：空间缩小了，碰撞**必然存在**。
- **计算困难性**（复杂性）：找到它**需要 2¹²⁸ 量级的操作**，而宇宙年龄才 10¹⁰ 秒。

## 4. 原理：为什么最好的哈希函数内部藏着一个可逆的零件

这是第 12 章整堂课的高潮，也是很多人（包括不少从业者）没想清楚的设计：

> 「哈希天然会销毁信息……但这里有个悖论：在我们造出的所有最好的哈希函数内部，最大的一块部件却是一个**保熵**变换：一个置换。」
> ——第12章，chapter-12.md:109

> 「这个核心部件把输入一一映射到输出。不仅如此，正着跑、倒着跑，它都能高效执行。收缩和不可逆，则来自顶层薄薄的一层：一次删除，再把被删掉的那部分原输入异或之后附在末尾。」
> ——第12章，chapter-12.md:109

### 4.1 结构：压缩函数 + 截断层

书里描述的结构就是密码学上著名的 **Merkle–Damgård 结构**（以 Ralph Merkle 和 Hans Damgård 命名，MD5、SHA-1、SHA-2 都用它）：

```
原始消息 M（任意长度）
   │
   ├─ 填充：对齐到 512 位（SHA-256）并写入长度
   │
   ▼
压缩函数 f（就是那个"保熵置换"，反复调用）
   │
   ▼
链值 h（256 位）
   │
   ▼
输出
```

关键在于：**不可逆性不在压缩函数里，而在最外面那一层"截断"。**

### 4.2 为什么不能把不可逆直接做进轮函数

书里给出了理由，这段论证非常漂亮：

> 「如果你直接把不可逆做进去，就控制不了熵在什么时候被销毁。一个不可逆的轮函数只要反复应用足够多次，大约一半的熵就会坍缩，协议的安全性也跟着一起垮掉。所以，哪怕销毁信息就是你最终的目的，最好也把负责这件事的那一块干干净净地单独分出来——按照你自己的意愿，在算法里一个精确的位置上销毁信息。」
> ——第12章，chapter-12.md:113

翻译成人话：

一个多轮哈希函数会被反复用上亿次（分块处理超长输入）。如果**每一轮**都做一点不可逆的小操作，那么**信息会在你不知道的某个轮次被提前毁掉**。你想藏的东西可能在你打算藏它之前就没了。

**可逆的置换把"信息何时被销毁"这件事，牢牢交到你手上。** 你想要多少熵损失，在哪个位置损失，损失多少，都可以精确控制。

### 4.3 现实中的另一种解法：海绵函数

SHA-3（Keccak）走了相反的路子：不截断，而是**把整个状态当成一个置换去反复搅**（这就是 chapter-12.md:327 之后泽在想的"把终态丢进沙盒倒着放"）。它的输出是从搅完的状态里"挤"出来的。

这就是 Merkle–Damgård 和海绵的分工对比：

| | Merkle–Damgård（MD5/SHA-1/SHA-2） | 海绵（SHA-3/Keccak） |
| --- | --- | --- |
| 状态 | 256 位 | 大得多（如 1088 位） |
| 不可逆发生在 | **最外层截断** | 反复挤压的每一次 |
| 天然抗长度扩展 | 否 | **是** |
| 设计哲学 | "最后一步集中销毁" | "全程均匀销毁" |

### 4.4 一个真实的反面教材：长度扩展攻击

Merkle–Damgård 的结构有一个真实存在的弱点，叫**长度扩展攻击**：

```
原文 M = "转账 100 元给甲" + 填充 + 长度
已知：H(M)、长度 |M|
攻击者不需要知道 M，就能算出：
       H(M || 填充' || 任意尾巴)
```

也就是说，攻击者可以在原文后面**悄悄追加内容**，让新消息的哈希和攻击者算出来的一致。

**这在现实中造成过真实事故**：2018 年，Google 和 Cloudflare 的 API 签名被攻击者利用长度扩展伪造出有效签名（后来用 HMAC 修正了——HMAC 就是在哈希外面套一层密钥，使得攻击者拿不到"可继续计算的中间状态"）。

**故事的要点**：哈希函数本身没问题，出问题的是**用法**。「哈希 = 密码」或者「哈希 = 签名」都是错的。

## 5. 关键参数与真实世界的取值

| 算法 | 输出 | 年份 | 状态 |
| --- | --- | --- | --- |
| MD5 | 128 位 | 1992 | **已完全破**，碰撞可秒级构造 |
| SHA-1 | 160 位 | 1995 | **已被攻破**（2017 年 SHAttered 造出真实碰撞） |
| SHA-256 | 256 位 | 2001 | 安全，广泛使用 |
| SHA-3 (Keccak) | 256/512 位 | 2015 | 安全，抗长度扩展 |
| BLAKE3 | 256 位 | 2020 | 设计目标是软件极快，近年在工具链里很常见 |

**安全位数怎么算**：搜到碰撞约需 $2^{n/2}$ 次操作（生日悖论，详见 [27 二项式分布](../math/27-binomial-distribution.md)）。所以：

- MD5（128 位）→ 约 $2^{64}$：1992 年时算不动，今天已随手可破。
- SHA-1（160 位）→ 约 $2^{80}$：2017 年被真实攻破。
- SHA-256（256 位）→ 约 $2^{128}$：目前远远安全。

**为什么"暴力找原文"更难**：那是 $2^{256}$，比找碰撞多了天文数字倍。

## 6. 容易误解的地方

**误解一：「哈希是加密的逆操作。」**
哈希**没有密钥**，任何人都能算。它和加密不在一个维度上：加密是「加锁」和「配钥匙」，需要两把东西；哈希是「盖章」，一个人就能盖，但盖完看不出原文。

**误解二：「不可逆 = 安全，所以哈希可以存密码。」**
**恰恰相反。** 哈希单向，所以攻击者拿到哈希后可以用**字典和彩虹表**离线猛试。如果你的密码是 `123456`，它在常见密码表的第一行。存密码的正确做法是**加盐 + 用慢哈希**（bcrypt / scrypt / Argon2），故意让计算变慢一千倍，让攻击者的离线爆破也变慢一千倍。

**误解三：「哈希一定不会撞。」**
MD5 和 SHA-1 都被实际攻破了。**安全措辞永远是"在计算上不可行"，不是"不会"。**

**误解四：「第 12 章说的置换可以随便逆着用。」**
书里泽很兴奋地想把一个置换倒着放——这在数学上完全合法。麻烦在于：**逆置换用起来，等于丢掉了这个结构提供的全部安全性**。真实世界里的同类操作（白盒密码学、线性攻击）都需要在有额外信息（密钥）的前提下才成立。

## 7. 自己动手试试

**A. 亲手构造一次 SHA-256 的填充。** 假设你的消息是 3 字节的 `"abc"`。

- 3 字节数据 + 1 字节 `0x80` 填充标记 = 4 字节
- 补 `0x00` 到 55 字节
- 最后 8 字节写消息长度的比特数：3 × 8 = 24

凑成 64 字节（512 位）一块。这个"补齐 + 写长度"是 Merkle–Damgård 的标志，所以长度信息**一定在**消息里——**这正是长度扩展攻击的入口**。

**B. 验证"抗碰撞"有多难。** 随便找在线哈希工具，对 `hello` 和 `hello `（多一个空格）分别求哈希，看它们完全不同。改一个字符，输出就面目全非——这就是雪崩效应。SHA-256 的雪崩强度指标是：改 1 位，平均约有一半的输出位会翻转。

**C. 算一算暴力搜索的代价。** SHA-256 找碰撞约 $2^{128}$ ≈ $3.4 \times 10^{38}$ 次操作。假设全球所有计算机加起来每秒做 $10^{21}$ 次哈希（已经严重高估），需要 $3.4\times10^{17}$ 秒 ≈ **一亿年**。这就是"不可行"的量化含义。

## 8. 自测

**Q1.** 为什么说哈希函数在信息论上**必然**存在碰撞，但实践中却"撞不上"？这两个说法矛盾吗？

> **答案**。不矛盾，它们说的不是一件事。**必然存在**是鸽笼原理的结论：256 位的输出空间必然装不下无限多的输入，所以一定有碰撞存在。**撞不上**是关于**找到它**的难度的结论：找到一对碰撞需要 $2^{128}$ 量级的计算。所以"存在"是数学事实，"找不到"是工程事实。真正该说的是"在可预见的时间内找不到"。

**Q2.** Merkle–Damgård 为什么把不可逆性放在最外层，而不是每一轮里都做？

> **答案**。因为那样就**没法控制信息什么时候被销毁**。哈希函数会被反复调用上亿次（处理超长消息），如果每轮都销毁一点熵，信息会在你没安排的时刻消失——你想藏的秘密可能半路就没了。把可逆的置换放在里面、只在最外层精确地截断一次，熵的损失就完全在你的控制之下。（chapter-12.md:113 的原话就是这个意思。）

**Q3.** 长度扩展攻击在做什么？为什么加个密钥（用 HMAC）就能挡住它？

> **答案**。Merkle–Damgård 把上一步的链值直接喂给下一步，攻击者只要知道 $H(M)$ 就能继续往后算，于是能在原文后面追加内容并算出正确的哈希。加了密钥之后（HMAC），每次哈希的输入里混入了只有双方知道的密钥，攻击者拿不到那个可继续计算的中间状态，推不下去，所以断掉了。
