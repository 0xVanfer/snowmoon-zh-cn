# 43 模拟器到现实的差距（Sim-to-Real Gap）

> 在模拟器里训练出来的东西，搬到现实里常常不好使。这个落差有专门的名字：**sim-to-real gap**。这一篇讲它是什么、为什么存在、以及现实中怎么跨越它。

## 1. 它是什么

**世界模型**（world model）指一个系统对"如果我这么做，会发生什么"的**可运行的内部模拟**。它可以是游戏引擎、物理仿真器、也可以是专门为训练 AI 造的合成环境。

**sim-to-real gap** 是指：

> 策略在模拟器（world model）里优化的目标，与在真实环境里的实际目标之间的差异。

这个差距无法用单个公式概括，它由很多小偏差累积而成：

| 偏差来源 | 具体例子 |
| --- | --- |
| **物理不精确** | 摩擦系数、空气阻力、材料弹性——仿真参数永远和真实差一点 |
| **几何与渲染** | 光照、阴影、纹理、镜头畸变 |
| **传感器噪声** | 相机噪点、IMU 漂移、GPS 抖动、丢帧 |
| **动力学** | 接触、碰撞、执行器延迟、马达响应 |
| **环境动态** | 行人、其他车辆、天气——仿真里你得自己放进去 |
| **任务本身** | 真实世界里其他主体的行为是不可完全预测的 |

**关键洞察：sim-to-real gap 不是 bug，而是"你用一个便宜的模型代替昂贵的真世界"的必然代价。** 真实世界每次试验要花真金白银、还有安全风险；模拟器可以跑一百万次。所以你**必须**用模拟器，也就**必须**承受这个差距。

## 2. 小说里它在干什么

第 30 章，泽国没有模型权重，只能通过 API 访问北极的**模拟环境**。而这个模拟环境是一个**世界模型**：

> 「但我能给你们一个次优的选择：北极那套模拟环境的 API 访问权限。里面包括北极无人机的模…」
> ——第30章，chapter-30.md:9

> 「既有完整的世界模型模拟…」（还有只针对输入模态的**部分模拟**，只给出分类结果）
> ——第30章，chapter-30.md:9

**这里有一个精妙的层次**：北极提供了两档 API——
- **完整世界模型**：可以运行整个仿真，能看到动态过程
- **部分模拟**：只接受图像输入，返回一个分类结果

**只有后者是能做梯度攻击的**（需要能反向传播求导），前者只能"跑一遍看结果"。这个区分非常准确，也说明**接口设计本身就决定了攻击能力**。

然后是**专门研究 sim-to-real gap 的小组**：

> 「为了验证模拟器的效果，他们还在一套夜间环境里跑了模拟——那套环境精确复刻了当晚早些时候一场小规模战斗的真实场景。另一个小组由两名研究员和几个翡翠实例组成，他们开始研究**如何自动分析夜间环境下模拟与现实的偏差**，进而学会怎样构造发给模拟器的查询，让结果更贴近真实战场。」
> ——第30章，chapter-30.md:63

**这段是全书最贴近真实研究前沿的描写。** 它精确地描述了一个真实存在的研究方向：

> **不是去修模拟器，而是去"学会如何查询模拟器"，让模拟器给出更接近真实的答案。**

最后是书里对迁移性的清醒认知：

> 「最后的攻击会出现在真实世界里，而不是模拟器里，所以我们能做到的，只是**筛出在不同模拟器上都稳健的改动**。」
> ——第29章，chapter-29.md:275

## 3. 直觉：反复做同一道应用题

你在数学书上刷了 500 道二次函数应用题，个个解得又快又准。考场上给你一道**同样是二次函数、但描述换成"一辆车刹车距离与速度的关系"**的题——你可能会犹豫，因为"应用题"的措辞不同。

**sim-to-real gap 就是这个差别，但它更根本**：它不是题目表述的差别，而是**分布本身**的差别。

**第二个类比**：你在一款游戏里练了 1000 小时的枪法，换到另一款相似但物理引擎不同的游戏，开局会被打得很惨。**你练的不是"射击"，是"那个游戏里的射击"。**

## 4. 原理与现实的破解手段

现实中有好几种成熟的跨越方法，全部都是"承认差距存在，然后想办法补偿"：

### 4.1 域随机化（Domain Randomization）

**思路**：既然不知道真实世界长什么样，就**把模拟器变得尽可能"宽"**——在训练时随机化光照、纹理、摩擦、质量、噪声等参数，逼策略学会在**一堆不同的世界**里都能work。

**隐含赌注**：真实世界落在这堆随机化出来的世界里。

- **优点**：简单有效，物理上不需要建模准确性
- **致命缺陷**：**必须有"覆盖真实分布"的保证**。如果某个真实因素根本不在随机化范围内（细如发丝的绳子、反光的湿地面），策略就完全没有准备

**书中隐含的就是这个**：他们"换不同参数的模拟器去试"（chapter-29.md:275）——这就是域随机化。

### 4.2 系统辨识（System Identification）

**思路**：反过来，从真实世界收集数据，**去估计模拟器的参数**，把模拟器校准得更准。

- 书中 chapter-30.md:63 的"自动分析模拟与现实的偏差"，正是这个思路
- **优点**：有针对性
- **缺点**：**只能修正你测到过的偏差**；而且这里有个现实困难——你**没有足够的真实数据**（那正是你才需要模型的原因）

### 4.3 sim-to-real 微调（Fine-tuning）

**思路**：在模拟器里训出策略 → **在真实世界里用极少数据做微调** → 迁移到真实。

- 书中对应的正是**用查询结果微调自己的模型**（chapter-30.md:27）
- 关键在"极少数据"，所以常配合**残差学习**（只学"现实与模拟的差"）

### 4.4 迁移学习与多模型集成

**思路**：不赌单一模拟器。在**多个不同架构的模拟器**上优化，挑那些**在所有模拟器上都有效**的改动。

**理由**：如果一个改动只在模拟器 A 上有效，那它多半利用了 A 的**特有缺陷**；如果它在 A、B、C、D 上都有效，那它更可能利用了**目标模型自身**的脆弱性——而这才是可迁移的。

**这是书中第 29:275 行"筛出在不同模拟器上都稳健的改动"的数学依据**（详见 [38 对抗补丁](38-adversarial-patch.md)）。

### 4.5 集成与随机化策略

**思路**：不用单一最优策略，而用**一组随机策略**，并让它们本身成为不可预测。

这招很聪明：它**不要求你的策略在真实环境最优，只要求它在真实环境足够"不行为"**。这正是" unpredictability as a defense"。

## 5. 关键：差距到底有多大——书里给了数字

**这是全书最值得记住的攻防数据**（第 30 章）：

| 阶段 | 效果 |
| --- | --- |
| 初始对抗补丁 | 侦测时间优化 5% |
| 改进后 | 11% |
| 再优化 | 翻倍 |
| 再优化 | **再翻倍** |
| 维里迪亚军方伤亡比 | 一度拉到 10:1 以上，后回落至 6:1 |
| **北极切断模拟 API 后** | **跌至 1.5:1** |

**最后一行的含义**：**仅靠"能查询模拟器"这一点，泽国就把战损比从 1.5:1 拉到 6:1——整整 4 倍的差距。**

这说明：

1. **知识的不对称（谁能查询对方的模型）比模型本身的强弱更重要。**
2. **一旦这个不对称被切断，优势立刻蒸发。**

**这是本书对"信息战"最量化的一次表达**，也是本书世界观里最有现实意义的洞察之一——在 AI 时代，**谁能查询别人的模型，谁就能改造物理世界。**

## 6. 容易误解的地方

**误解一：「sim-to-real gap 是模拟器做得不够好。」**
**部分对，但更准确的说法是**：模拟器在**你测量的维度上**可以做到极精确（现代物理引擎能精确模拟流体、结构），但你**无法穷尽所有相关维度**。问题是开放式的，改进是渐进的。

**误解二：「域随机化总是能work。」**
**不保证。** 它需要一个**覆盖性假设**：真实世界落在你随机化出来的分布内。**如果某个真实因素没被随机化，策略就完全没准备。** 而且随机化太多会让任务变得几乎不可能学（"游戏"变得太难），太少又覆盖不足——**这是两难，没有免费午餐。**

**误解三：「在多个模拟器上都有效 = 在现实里也有效。」**
**只是一个启发式，不是保证。** 多个模拟器可能**共享同一个建模错误**（都是同一个物理引擎做的），那么"在它们上都work"并不意味着在现实里 work。**书里第 29:275 用"希望"这个词是准确的——"跑个100万轮之后，希望我们能得到一套在现实中相当管用的东西"。**

**误解四：「世界模型越完整越好。」**
**不一定。** 世界模型越完整，查询越真实，但**接口越受限**。书里那个区分很准：
- **完整世界模型**（能跑完整仿真）→ 只能"跑一遍看结果"，**不能求梯度**
- **部分模拟**（只返回分类结果）→ **能求梯度**，但丢失了动力学信息

**这是一个真实的权衡**：你选择暴露多少信息给对手，是在"信息保真度"和"可攻击性"之间选。**完全没有信息（只有分类结果）反而更好防守——因为对手没法攻击一个只能问问题、无法求导的黑箱。** 这正是零阶方法需要"标量信号"的原因（见 [39](39-black-box-query-attack.md)）。

**误解五：「有了 sim-to-real gap，就无法用AI做决策。」**
**不是无法，而是需要系统级防护。** 现实中大量系统就是靠冗余+验证+权限隔离在使用 AI——单个模型不需要"绝对可靠"。**这正是"关键基础设施必须防御纵深"的具体含义。**

## 7. 自己动手试试

**A. 测量你的"简化模型"与真实世界的差距。** 选一个你熟悉的物理现象（比如"球从斜面滚下"），写一个理想模型（比如"无摩擦、恒定重力"），然后真实地观察：
- 球真的按理想模型滚吗？
- 球面材质有影响吗？斜面粗糙度呢？空气阻力呢？
- **你能写出的理想模型有几条假设？其中几条在真实中不成立？**

**这个练习会让你亲身体会：sim-to-real gap 不是一个神秘的"gap"，而是一长串"可列举但难全部列举"的理想化假设。**

**B. 设计一个域随机化的实验。** 假设你要训练一个"抓杯子"的机械臂。你会随机化哪些参数？
> 参考：杯子材质、颜色、纹理、位置、朝向、桌面材质、光照、摩擦系数、相机角度、遮挡物。
> **然后问自己：有没有哪个"真实世界的因素"你没列出来？** 答案通常是"有"——这就是域随机化的覆盖性假设的破口。

**C. 量化"查询次数"的价值。** 书里说百万次查询把侦测时间从 5% 优化到"翻倍再翻倍"。假设：
- 无查询：效果 = 5%
- 10 万次查询：效果 = 11%
- 100 万次查询：效果 = 22%
- API 切断：效果 ≈ 0（跌回基线）

**画一条"效果 vs 查询次数"的曲线，你会看到一个快速上升然后饱和的形状。** 关键认识：

> **前几千次查询的边际价值最大。** 之后每增加十倍查询，收益递减。**所以"是否开放查询"这个开关，比"开放多少"更重要。**

## 8. 自测

**Q1.** sim-to-real gap 为什么无法通过"把模拟器做得更准"彻底消除？

> **答案**。因为差距的根源是**相关维度的开放性**，不是精度不足。你可以完美模拟流体的每一种已知物理现象，但真实世界里总有你没想到的维度（未建模的气体效应、微观表面结构、超出量程的传感器行为等）。改进是渐进的，**消除是不可能的**。sim-to-real gap 是"用便宜模型代替昂贵真世界"的必然代价，只能管理、不能消除。

**Q2.** 为什么要"筛出在不同模拟器上都稳健的改动"？

> **答案**。因为**只在一个模拟器上取得最优的改动，很可能只利用了那个模拟器的特有缺陷**——到了别的环境就失效，这叫**过拟合到模拟器**。
> 在多个不同架构的模拟器上都有效的改动，更可能抓住了**不同模拟器共享的**弱点（也就是目标模型本身共有的脆弱性），因而更可能迁移到真实世界。
> 但要诚实说：**这只是启发式，不是保证**。多个模拟器可能共享同一个建模错误。书里第 29:275 用"希望"这个词是准确的。

**Q3.** 世界模型的接口设计（暴露多少信息）如何影响它的安全性？

> **答案**。影响极大，书中第 30:9 给出了两种对比：①**完整世界模型**（能跑完整仿真）暴露了动力学信息，只能"跑一遍看结果"；②**部分模拟**（只返回分类结果）虽然丢失了动力学信息，但**反而能求梯度**——正因为它是可微的输入-输出对（$\text{输入图像} \to \text{分类结果}$），所以对方可以梯度攻击。**这意味着"暴露的信息越少"有时候反而更安全**——完全没有信息（纯黑箱、只有查询）可以逼迫攻击者用零阶方法（见 [39](39-black-box-query-attack.md)）。**一个只暴露最终分类结果的接口，比一个暴露完整模拟轨迹的接口更难被精确攻击。** 这是"少即是安全"在 AI 时代的一个具体体现。
